# 002 물어보기를 서버에 잇는다 — 진짜 답, 하나로 이어지는 대화, 기록 쌓기

> 상태: 완료 (2026-10-03) — 화면 시험은 첫 출시판 개발을 마친 뒤 몰아서 한다(Julian 지시)
> 근거: SPEC-ASK-01 · SPEC-ASK-02 · SPEC-ASK-03 · SPEC-ASK-04 · SPEC-ASK-05 · SPEC-ASK-08 · SPEC-ASK-10
> 서버 쪽은 [common/004](../common/004-real-answer.md)(Cloud Run 배포 완료). 계약: [api-contract](../../architecture/api-contract.md) `/v1/ask`

## 목표

물어보기 화면의 예시 고정값을 걷어내고 `POST /v1/ask` 를 부른다. 질문과 답은 기기에 저장해 앱을 다시
열어도 하나의 타임라인으로 이어지고, 되묻기에 고른 답과 답변에 섞인 사실은 L2 기록으로 쌓인다.

## 이 task 에서 하지 않는 것

- 답변 피드백(SPEC-ASK-06) — 서버가 피드백을 저장할 곳(Neon)이 생긴 뒤 ask/003 에서
- 일일 한도 화면(429 · 광고 충전 · 절약 모드 선택지) — 서버 한도와 함께 common/005 에서
- 지난 대화 검색·보관함(SPEC-ASK-10 의 "다음") · 최근 질문 이어보기(SPEC-HOME-04)는 home/002 에서
- 답변 완성도 다듬기 — 앱 화면이 다 된 뒤(README 다음 시작점)

## 먼저 정한 것

1. **서버 주소** — `EXPO_PUBLIC_API_URL`(빌드 때 박힌다). 없으면 Cloud Run 주소. 로컬 서버로 시험할 때만
   `.env.local` 에 `EXPO_PUBLIC_API_URL=http://localhost:8000` 을 둔다
2. **자동 재시도 없음** — 같은 clientMessageId 재요청을 서버가 아직 같은 응답으로 돌려주지 못한다(common/005).
   다시 보내면 모델 호출이 한 번 더 나가므로, 실패하면 「다시 시도」 버튼으로 사용자가 고르게 한다
3. **실패한 시도는 저장하지 않는다** — 오류 말풍선은 화면에만 있고, 다시 열면 질문만 남아 있다
4. **되묻기가 열려 있을 때 입력창에 친 글은 그 되묻기의 답이다** — 칩과 같은 길로 기록에 남기고
   원래 질문을 다시 보낸다. "잘 모르겠어요"는 기록하지 않고 `mode: "eco"` 로 다시 보낸다(SPEC-ASK-03 회피)
5. **답변의 records 제안은 자동 저장하고 「기록됨」 칩으로 보인다**(ask.md L2 추출 규칙). 칩을 누르면
   지우기를 고를 수 있다. 같은 문구의 기록이 이미 있으면 다시 넣지 않는다
6. **모델에 보내는 기록은 최근 30개** — 서버가 무료 티어·절약 모드에서는 모델로 넘기지 않는다(common/004)

## 단계

1. `src/data/api.ts` — 요청·응답 타입(계약 그대로), `postAsk`, 오류 모양(`ApiError`: status · code), 시간 제한 65초
2. 대화 저장 — `chat_message` 테이블(backend 기기 DB 스키마) · `db.web.ts` 의 localStorage 판 · `src/data/chat.ts`
   · `ChatProvider`(홈의 최근 질문도 같은 것을 본다)
3. 묻기 흐름 — `src/hooks/use-malkong.ts`: 보내기 · 되묻기에 답하기 · 다시 시도. TanStack Query `useMutation`
4. 화면 — 날짜 구분선 · 질문 버블 · 처리 현황(진행 중 순환 문구, 끝나면 단계별 한 줄 결과로 접힘) ·
   답변(수위 표시 · 출처 · 근거 없음 표시 · 절약 모드 표시 · 기록됨 칩) · 되묻기 칩 · 위험 신호 카드(119 전화) · 오류
5. 플로팅 버튼에서 넘어온 질문(`?q=&t=`)을 한 번만 보낸다
6. 문서 — ask.md 「현재 구현」, app-design 스택 표(TanStack Query 도입됨, 경고 색 토큰)
