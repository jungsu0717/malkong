## 목표

Julian(2026-10-08): 「대화가 길어질수록 무거워지고 맥락 찾기도 어렵다. 대화방을 나눠야 하나?」 → 나누지 않는다(decisions/020). 대신
무거움은 그리는 양으로, 찾기는 구조층(날짜 · 기록)에서 원문으로 가는 점프로 푼다. 확인해 보니 대화는 전체를 한 번에 읽어 일반 스크롤
화면에 다 그리고 있었다.

## 정한 것

- **최근 50줄만 그린다.** 켤 때 마지막 50줄, 맨 위 「이전 대화 더 보기」를 누르면 50줄씩 늘린다. 위에 붙여도 보던 자리가 밀리지 않게
  `maintainVisibleContentPosition`(iOS · Android)
- **「대화 보기」 · 「이날 나눈 대화」로 넘어온 줄이 창 밖이면 그 줄까지 창을 넓힌 뒤 스크롤한다** — 그리는 중에 맞춘다(일정 탭의 `?day=` 와 같은 방식).
  읽는 중에 넘어오면 다 읽은 뒤에 맞춘다
- **줄 위치는 모든 말풍선이 적는다**(질문 · 답 · 위험 신호 · 브리핑) — 전에는 질문만 적어서 날짜 점프의 목표가 질문뿐이었다
- **일정 탭의 고른 날에 「오늘(이날) 나눈 대화 · 질문 N개 · 첫 질문」 한 줄** — 질문이 있던 날만. 누르면 대화의 첫 질문 자리로.
  날짜별 요약은 `chatByDay(messages)`(`src/data/schedule.ts`)
- **기록 → 그 대화**는 이미 있다(기록 화면 「대화 보기」, SPEC-BABY-06). 그대로 둔다
- 기기 DB 에서 대화 전체를 읽는 것은 그대로 — 켤 때 수천 줄도 밀리초 단위다. 그리는 쪽이 비용이었다. 읽기 페이징은 느려질 때 다시 본다
