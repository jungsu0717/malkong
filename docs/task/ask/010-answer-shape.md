# 010 답의 모양 — 결론 → 왜 → 지금 할 것 → 진료 기준, 우리 아기를 앞머리에

> 상태: 진행 (2026-10-08) — 프롬프트 · SPEC 고침, 같은 질문 셋으로 전후 비교. 운영 반영은 Julian 승인 뒤 배포
> 근거: SPEC-ASK-01(이 task 에서 답의 순서와 길이, 「우리 아기 앞머리에 짚기」를 평시로 올린다) · SPEC-ASK-08 ·
> [decisions/011](../../decisions/011-useful-general-answers.md)

## 목표

Julian(2026-10-08): 「답이 일반 LLM 답변이 아니라 요약된 내용만 나오는 것 같다」 → 실제 답 셋(사실 · 일반 · 판단)을 받아
같이 봤다. 길이(128~185자, 3~4문장)는 폰에서 읽기에 적당했고, 빠진 것은 둘이었다 — 기록이 있는데도 「우리 아기」로
말하지 않는 것, 「이 월령에 흔한 일인지」 같은 왜가 없는 것. 판단 답(뒤집기)은 기준 → 흔한 모습 → 할 것 → 진료 기준이
다 있어 가장 좋았다. 그 모양을 모든 답의 기본으로 삼는다. 「3~5문장」은 SPEC 이 아니라 프롬프트에만 있던 구현 선택이었다.

## 정한 것

- **답의 순서 넷**: 결론 → 왜 그런지(이 월령에 흔한 일인지) → 지금 집에서 할 것 → 진료가 필요한 기준(그런 기준이 있는
  질문에만, 끝에 한 번). 번호 · 제목 없이 자연스러운 문장으로. 길이는 3~5문장 → **4~6문장**
- **우리 아기를 앞머리에**: 질문과 관련된 기록이 있으면 첫 두 문장 안에서 짚는다(「안아서 재우고 계시니」). 기준은 우리 아기
  월령에 대 주어 말한다(4개월 아기에게 「두 달쯤 뒤인 6개월 무렵」). 기준의 숫자 · 시기는 바꾸지 않는다
- 일반 답에 「이 월령에 흔히 있는 일이면 그렇다고 한 문장」 — 부모가 가장 알고 싶은 것
- 일정 · 방법을 묻는 사실 질문에는 진료 권유를 붙이지 않는다
- 길게 쓰지 않는다 — ChatGPT 식 긴 글은 한 손 읽기와 맞지 않고, 길어질수록 근거 없는 말이 섞일 자리가 는다

1바퀴의 두 퇴보는 「결론부터」가 판단 질문에서 안심 결론을 부르고, 기록 문장이 앞에 오며 「일반적으로는」이 밀린 것 →
판단 질문은 기준을 첫 문장으로 · 결론 문장에 「일반적으로는」 · 내부 이름 금지로 고쳤고 2바퀴에서 둘 다 사라졌다.
2바퀴의 「두 달쯤 뒤」는 프롬프트에 적어 둔 예시 문구를 모델이 그대로 베낀 것이라 예시를 빼고 「기준 월령에서 아기 월령을
빼서 계산, 확실하지 않으면 남은 기간은 말하지 않는다」로 바꿨다. **이 마지막 수정은 두 바퀴 규칙에 따라 다시 재지 않았다** —
