# constitution — 말콩의 불변 원칙

이 문서는 개별 SPEC 보다 위에 있다. SPEC·task·코드가 여기와 충돌하면 여기가 이긴다.
바꾸려면 이 문서를 먼저 고치고 이유를 changelog 에 남긴다.

## 제품 원칙

1. **근거 없는 답을 근거 있는 척 내보내지 않는다.** 기반 지식은 재사용이 허용된 공공 출처 화이트리스트로만
   구축하고, 원문을 베끼지 않고 뜻을 재서술하며 항목마다 출처를 단다. 공공 지식에 근거가 없는 질문에는
   일반 정보임을 밝히고 그렇게 표시해서 답한다(SPEC-ASK-08). 상업 서적의 내용을 재제공하지 않는다.
2. **의료 조언의 경계를 지킨다.** 위험 신호(고열·탈수·호흡곤란·경련 등)는 항상 병원·119 안내로 고정하고,
   모든 답변 화면에 「버디의 답은 응급 상황을 대신할 수 없어요」 한 줄을 둔다(119 · 응급실 안내는 위험 신호 답 본문이 한다). 「참고용」 고지는 의학 정보 고지와 약관에 둔다(Julian, 2026-10-12 —
   답마다 붙이는 「참고용」은 읽는 사람에게 짐이고, 법적 경계는 약관 · 고지가 진다). 진단·처방에 해당하는 답을 만들지 않는다.
3. **한 번 물은 것은 다시 묻지 않는다.** 되묻기는 답변에 필요한 1~2개까지만, 답은 기록으로 저장하고
   저장한 사실을 사용자에게 보여준다.
4. **아기 데이터는 민감 정보다.** 초기에는 기기 안에만 저장하고, 서버 저장은 로그인·명시적 동의와 함께만
   도입한다. 광고에 아기 건강 데이터를 넘기지 않는다.
5. **기록은 빨리 받고, 버디가 해석한다.** 수유 · 기저귀 · 잠 · 체온 · 키와 몸무게는 한두 번 눌러 남기게 하고,
   쌓인 기록은 버디가 읽어 우리 아기 이야기로 돌려준다(답 · 브리핑 · 그래프). 대화에서 나온 사실도 기록이 된다.
   기록을 다그치지 않고(남기지 않았다고 탓하는 말을 쓰지 않는다), 기록 앱의 모든 것(앨범 · 일기 꾸미기)을 따라가지 않는다.

## 개발 원칙

6. **SPEC 이 먼저다.** 근거 SPEC 없는 기능 코드를 만들지 않는다. SPEC 이 모호하면 지어내지 않고 묻는다.
7. **검증은 구현과 분리한다.** task 를 끝낼 때는 완료 조건(SPEC 문장)과 실제 동작을 대조해 확인하고,
   통과시키려고 조건을 몰래 완화하지 않는다. 규모가 커지면 검증을 별도 세션(에이전트)에 맡긴다.
8. **품질 게이트**: 앱은 `npx tsc --noEmit` + `npx expo lint`, 서버는 `uv run ruff check .` +
   `uv run ruff format --check .` + `uv run pytest` 를 통과하기 전에는 끝났다고 하지 않는다.
9. **스택·스타일의 정본은 [app-design](app-design/README.md)** 이고, 무게 있는 선택의 이유는
   [decisions](decisions/README.md)에 남긴다.
