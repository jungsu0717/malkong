# constitution — 말콩의 불변 원칙

이 문서는 개별 SPEC 보다 위에 있다. SPEC·task·코드가 여기와 충돌하면 여기가 이긴다.
바꾸려면 이 문서를 먼저 고치고 이유를 changelog 에 남긴다.

## 제품 원칙

1. **출처 없는 답변은 내보내지 않는다.** 기반 지식은 재사용이 허용된 공공 출처 화이트리스트로만 구축하고,
   원문을 베끼지 않고 뜻을 재서술하며 항목마다 출처를 단다. 상업 서적의 내용을 재제공하지 않는다.
2. **의료 조언의 경계를 지킨다.** 위험 신호(고열·탈수·호흡곤란·경련 등)는 항상 병원·119 안내로 고정하고,
   모든 답변에 참고용 고지를 붙인다. 진단·처방에 해당하는 답을 만들지 않는다.
3. **한 번 물은 것은 다시 묻지 않는다.** 되묻기는 답변에 필요한 1~2개까지만, 답은 기록으로 저장하고
   저장한 사실을 사용자에게 보여준다.
4. **아기 데이터는 민감 정보다.** 초기에는 기기 안에만 저장하고, 서버 저장은 로그인·명시적 동의와 함께만
   도입한다. 광고에 아기 건강 데이터를 넘기지 않는다.
5. **기록 앱과 경쟁하지 않는다.** 우리의 기록은 답변 정확도를 위한 최소 컨텍스트다.
   전량 수동 로깅을 요구하는 기능을 만들지 않는다.

## 개발 원칙

6. **SPEC 이 먼저다.** 근거 SPEC 없는 기능 코드를 만들지 않는다. SPEC 이 모호하면 지어내지 않고 묻는다.
7. **검증은 구현과 분리한다.** task 를 끝낼 때는 완료 조건(SPEC 문장)과 실제 동작을 대조해 확인하고,
   통과시키려고 조건을 몰래 완화하지 않는다. 규모가 커지면 검증을 별도 세션(에이전트)에 맡긴다.
8. **품질 게이트**: `npx tsc --noEmit` + `npx expo lint` 통과 전에는 끝났다고 하지 않는다.
9. **스택·스타일의 정본은 [app-design](app-design/README.md)** 이고, 무게 있는 선택의 이유는
   [decisions](decisions/README.md)에 남긴다.
