# 018 데일리 브리핑은 안부 — 기기 안 규칙과 문구 틀로

> 상태: 확정 (2026-10-04, Julian 결정)

## 맥락

아침 브리핑의 챙길 것은 월령 일정에서 고른 줄이라 날마다 거의 같았다. Julian: 매일 보내는 만큼 어제 대화에 열이 났으면
열은 어떤지, 자꾸 게워 냈으면 잘 먹었는지 — 부모의 마음으로 아기를 챙기고, 친정엄마의 마음으로 부모를 챙겼으면 좋겠다
(많이 칭얼댔으면 잠은 좀 잤는지, 아기 잘 때 같이 자는 게 최선이라는 팁). 오늘 챙기면 좋을 것과 기록하면 좋을 것도 자연스럽게.

## 결정

1. **데일리 = 안부 + 오늘 하루** — 아기 안부 · 부모 안부 · 오늘 챙기면 좋을 것 · 기록하면 좋을 것 · 이번 주 일정 한 줄.
   월간 일정은 주간 · 월간 브리핑으로 옮긴다([017](017-schedule-tab-and-inbox.md)). 정의는 SPEC-HOME-06
2. **기기 안 규칙과 문구 틀로 만든다** — 어제 · 그제 대화와 기록에서 신호(열 · 게움 · 덜 먹음 · 접종 · 변 · 기침 · 보챔 · 밤잠)를
   찾고, 신호마다 검토한 문구를 쓴다. 모델을 부르지 않는다
3. **안부는 묻기만** — 안심 단정 · 진단을 쓰지 않고, 걱정되는 답은 대화로 넘겨 위험 신호 규칙을 거친다.
   관련 위험 신호 L1 이 있으면 출처와 함께 붙인다
4. **팁은 승인된 L1 에서만** — 부모 돌봄 팁은 L1 에 없어 화이트리스트 출처에서 새로 만들고 Julian 이 승인한다(task common/013)

## 기각한 대안과 이유

- 모델이 브리핑을 쓰기 — 매일 모든 사용자에게 한 번씩 부르니 지출 한도를 쓰고, 앱을 열 때 기다려야 하고, 어제 대화를
  기기 밖으로 보내야 한다. 먼저 말을 거는 문장은 위험 신호 검사를 거치지 않아 의료 경계(원칙 2)도 지키기 어렵다.
  써 보고 문장이 딱딱하면 다듬기만 모델에 맡기는 2단계를 열어 둔다
- 서버가 밤마다 만들어 원격 푸시 — 서버에 기기 토큰과 기록 시점이 있어야 한다(원칙 4). backend 「능동 브리핑」 2단계(가족 공유 이후)
