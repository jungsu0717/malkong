# 019 한도는 사람에게 넉넉하게, 돈은 서버 전체의 하루 천장으로 막는다

> 상태: 확정 (2026-10-06)

## 맥락

Julian 의 두 조건: 돈이 새는 구조는 경계하고, 그렇다고 사용자가 조금 쓰고 막히는 구조도 싫다.

그때까지의 구조는 반대로 되어 있었다.

- 사람에게는 빡빡했다 — 보상형 광고 1편이 정밀 답변 1회였다
- 돈은 뚫려 있었다 — 정밀 답변을 다 쓴 뒤의 일반 기준 답(절약 모드)은 횟수 제한이 없었고, 문서와 달리 무료 티어가
  아니라 같은 유료 모델로 갔다. 마지막 안전장치는 Gemini 월 지출 한도(1만 원)뿐이라, 거기 닿으면 그 달의 모델 답이
  모두 멈춘다

숫자(2026-10-06): 답 1건은 약 1~3원(3.5 Flash-Lite, task common/003 실측 1원에 기록이 붙으면 늘어난다).
한국의 보상형 광고는 1,000회에 $12~22(게임 앱 기준, 새 앱은 더 낮을 수 있다) — 1편이 약 15~30원, 답 5~15건 값이다.

## 결정

정의는 [backend](../architecture/backend.md) 「일일 한도」.

- 정밀 답변(기록 반영) 하루 10회는 그대로
- 보상형 광고 1편 = **정밀 답변 5회**, 하루 **2편**까지
- 정밀 답변을 다 쓴 뒤의 일반 기준 답은 하루 **20회**까지 — 사람은 닿지 않는 수로, 자동으로 두드리는 남용만 막는다
- **서버 전체의 하루 비용 천장**(월 지출 한도 ÷ 30, 약 330원)을 넘으면 그날은 모델 답을 멈춘다. 위험 신호 안내는
  모델을 부르지 않으므로 계속 나간다. 운영자(가족) 기기는 천장과 상관없다
- 숫자는 모두 서버 설정값이다 — 실제 사용량을 보고 앱 업데이트 없이 바꾼다

## 기각한 대안과 이유

- **그대로 두기(광고 1편 = 1회, 일반 답 무제한)** — 광고 한 편 값에 비해 사용자에게 인색하고, 일반 답 무제한은
  비용 구멍이다
- **일반 기준 답을 무료 티어 모델로 보내기**(옛 backend 정의) — 질문 문장 자체에 "우리 아기가 38도예요" 같은 개인
  정보가 들어 있고, 무료 티어는 입력을 학습에 쓴다. 무료 할당량도 사용자 전체가 나눠 써서 불안정하다
- **하루 정밀 답변을 줄이기** — 돈은 줄지만 Julian 이 피하려던 "조금 쓰고 막히는" 구조가 된다
- **월 지출 한도에만 맡기기** — 월 중순에 닿으면 남은 날 내내 모든 사용자의 모델 답이 멈춘다. 하루 천장은 하루만 멈춘다
