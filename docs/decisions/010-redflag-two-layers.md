# 010 위험 신호는 규칙이 먼저 잡고, 놓친 것은 모델이 범주만 표시한다

> 상태: 확정 (2026-10-02)

## 맥락

backend 는 "위험 신호 판별은 모델에 맡기지 않고 규칙 필터가 선행한다"고 정했다. 그 규칙(글자 패턴)을
task common/004 에서 만들고 검증 에이전트로 두 번 시험했다. 1차에서 23건을 고쳤더니, 2차에서 처음 보는
부모 말투 181문장 중 **92문장(51%)만 잡았다** — "경련이 멈추질 않아요", "숨쉬기 힘든 것 같아요",
"입술이 파랬어요", "방금 40.5도 나왔어"를 놓쳤다. 고칠 때마다 새 말투에서 새 구멍이 나왔다.
한국어의 활용·줄임·띄어쓰기를 글자 패턴으로 다 덮을 수는 없다.

## 결정

두 겹으로 잡는다. 정의는 [backend](../architecture/backend.md) 「LLM 파이프라인」과
[ask](../menu-spec/ask.md) 「위험 신호 사전」.

1. **규칙이 먼저다.** 확실한 말은 규칙이 모델 없이 즉시 잡는다 — 모델이 없거나 한도를 넘어도 나간다
2. **규칙을 통과한 질문은 모델이 답하면서 위험 신호 범주(k-warn 8개 중 하나, 또는 없음)를 함께 표시한다.**
   표시가 있으면 서버는 모델의 답을 버리고 **고정 응급 안내**를 낸다

지키는 것은 원칙의 핵심 둘이다 — 응급 안내 문장은 모델이 쓰지 않는다(언제나 L1 항목 + 고정 문장),
모델이 없어도 확실한 응급 안내는 나간다. 바뀌는 것은 판별에 모델의 눈을 하나 더 쓴다는 것이다.

## 기각한 대안과 이유

- **규칙만 계속 다듬기** — 원칙은 그대로지만, 한 바퀴에 10~20분이 들고 바퀴마다 새 구멍이 나온다.
  응급 안내를 "몇 % 잡는다"로 둘 수 없다
- **판별을 모델에만 맡기기** — 모델이 없거나 느리거나 한도를 넘으면 응급 안내가 막힌다
- **아주 넓은 낱말 규칙(숨·경련·피가 나오기만 하면)** — 잡기는 하지만 "숨바꼭질", "머리둘레 40.5" 같은
  일상 질문까지 119 안내로 보내 앱을 쓸 수 없게 만든다

## 영향

- 모델에게 묻는 출력 JSON 에 위험 신호 범주 칸이 하나 는다 — 따로 한 번 더 부르지 않으니 비용이 늘지 않는다
- 규칙의 오탐을 줄이는 일(머리둘레·목 가누기 같은 성장 질문)은 계속한다. 잡는 범위는 모델이 메운다
- 무료 티어·절약 모드에서도 같은 두 겹이다 — 모델이 범주를 표시하는 데는 아기 기록이 필요 없다
