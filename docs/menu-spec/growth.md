# 일정 — 달력 · 브리핑 모아 보기 · 챙길 것 여정

> 근거: [main-design](../architecture/main-design.md) · [knowledge-layers](../architecture/knowledge-layers.md) ·
> [decisions/017](../decisions/017-schedule-tab-and-inbox.md)

세 번째 탭. 달력 위에 표준 일정(L1 접종·검진)과 우리 아기가 한 일(L2)과 브리핑을 날짜로 맵핑해 몰아 보고,
0개월부터의 전체 흐름은 **챙길 것 여정** 그래픽으로 본다. 매거진·읽을거리는 두지 않는다.

**자리** — 2026-10-04 「성장」 탭(이번 달 · 가로 타임라인)이 「일정」 탭이 됐다(decisions/017). 파일 이름과 SPEC ID(GROW)는
코드명처럼 그대로 둔다. 아기 상태 한 줄(SPEC-HOME-01)이 탭 머리에, 챙길 것(SPEC-HOME-02)이 달력 · 여정 · 주간 · 월간 브리핑에,
발달 포인트(SPEC-HOME-03)가 월간 브리핑에 들어온다.

## SPEC

### SPEC-GROW-01 달력 — 이번 주 한 줄, 펼치면 한 달
```
평시 ▸ 탭 위에 달력을 둬야 한다. 처음엔 이번 주 한 줄로 접혀 있고, 펼치면 한 달이 보이며, 앞뒤 주·달로 넘길 수 있어야 한다.
표시 ▸ 날마다 접종·검진 날짜 무렵 · 완료를 알린 날 · 주간·월간 브리핑이 온 날을 작은 표시로 구분해 보이고, 오늘은 눈에 띄게 한다.
고르기 ▸ 날을 누르면 그날의 데일리 브리핑 · 주간·월간 브리핑 · 그날 일정 · 그날 생긴 기록을 달력 아래에 보여야 한다. 처음엔 오늘.
시점 ▸ 표준 일정은 월령 기준이라 정확한 날이 아니다 — 생일에서 계산한 날에 「무렵」을 붙인다.
```

### SPEC-GROW-02 챙길 것 여정 — 표준과 우리 아기를 한 그림으로
```
평시 ▸ 0개월부터 월령을 따라 이어지는 길 위에 접종·검진·발달 항목을 정류장처럼 그리고, 우리 아기가 지금 어디쯤인지와
      지나온 정류장에서 무엇을 했는지(완료 알림 · 기록)를 한눈에 보여줘야 한다. 표준(L1)과 우리 아기(L2)는 모양과 색으로
      구분한다.
요약 ▸ 지금까지 할 것 가운데 한 것을 접종 · 검진 · 발달로 나눠 비율로 보여줘야 한다.
조작 ▸ 가로로 넘겨 보고, 정류장을 누르면 그 달의 항목과 상태가 열리며 거기서 완료를 알릴 수 있어야 한다(SPEC-HOME-02 완료 알림).
처음 ▸ 탭을 열면 지금 위치에 와 있고, 지나온 길이 차오르는 짧은 모션이 있어야 한다.
```
(2026-10-04 Julian — 타임라인 카드는 보기 어렵다, 우리 아기 탭처럼 그래픽으로 쉽게)

### SPEC-GROW-03 빈 자리의 의미
```
미래  ▸ 아직 오지 않은 정류장은 흐리게, 「앞으로」로 보여줘야 한다.
과거  ▸ 지난 정류장에 기록이 없으면 놓침으로 단정하지 않고 「기록이 없어요 — 했다면 알려 주세요」로 물어야 한다.
```

### SPEC-GROW-04 광고
```
평시 ▸ 탭 맨 아래에 배너 광고 1개를 두고 광고임을 표시해야 한다.
```

### SPEC-GROW-05 또래 부모들의 질문 묶음
```
평시    ▸ 여정의 각 정류장(월령)에, 그 월령 아이를 키우는 부모들이 자주 물은 질문 묶음을
         보여줘야 한다. 항목을 누르면 캐시된 답변을 바로 보여준다(LLM 재호출 없이 —
         backend 라우팅 ② 캐시).
미래 월  ▸ 아직 오지 않은 월에도 보여줘야 한다. 다가올 시기에 무엇이 궁금해지는지 미리 보는 것이
         이 기능의 값이고, 기록이 없어 비어 있던 미래 정류장을 이것이 채운다.
익명    ▸ 묶음은 익명 집계로만 만든다. 질문 원문을 그대로 노출해서는 안 되고 대표 질문은 재서술한다.
         표본이 작은 구간(같은 생일 단위 등)은 주령·월령 밴드로 넓혀 묶는다.
금지    ▸ 사용자끼리 답을 달게 해서는 안 된다. 답은 말콩이가 출처와 함께 단다(constitution 1).
```

### SPEC-GROW-06 함께 달려온 기록 — 성취 카드 (나중)
```
나중 ▸ 챙길 것을 해낸 순간을 우리 아기의 작은 성취로 보여줘야 한다.
나중 ▸ 100일·돌 같은 날에 그동안의 기록을 모은 성장 리포트 카드를 만들어, 사용자가 원하면
      이미지로 공유할 수 있어야 한다. 공유 이미지에는 처음에 이름·사진이 빠져 있어야 하고,
      넣을지는 사용자가 고른다.
나중 ▸ 아기가 자라 온 시간을 '달려온 거리'로 보여줘야 한다.
금지 ▸ 다른 아기·다른 부모와 순위를 매기거나 비교해서는 안 된다.
금지 ▸ 기록 개수나 연속 기록을 성취의 조건으로 써서는 안 된다 — 기록을 요구하지 않는다(constitution 5).
금지 ▸ 하지 못한 것을 벌점·끊긴 기록처럼 보이게 해서는 안 된다.
```
'달려온 거리'는 여정 길(SPEC-GROW-02)로 이어지는 브랜드 모티프 — 쪽쪽이 문 아기 버디가 달려온 길([decisions/015](../decisions/015-character-buddy.md)) —
를 잇는다. `미결:` 성취의 종류와 조건, 리포트를 만드는 날짜, 달려온 거리의 연출 — 이 기능의 task 를 시작할 때 정한다.

## HOW (현재 구현)

- 화면: 「성장」 탭(`src/app/(tabs)/growth.tsx`)의 「타임라인」 보기 — `src/components/baby/growth-view.tsx`.
  View 기반(스냅 스크롤·현재월 자동 시작·두 트랙·범례).
  현재 월은 저장된 생일에서 계산한 월령으로 잡는다.
- **현재 월에서 시작하기**: `contentOffset` 은 iOS 에서만 먹으므로, 내용이 깔린 뒤(`onContentSizeChange`)
  한 번 `scrollTo` 로 옮긴다. 웹·안드로이드에서 0개월부터 열리던 문제를 이렇게 고쳤다(2026-10-01).
- 월 컬럼은 저마다 가는 테두리를 둬서 한 달이 하나의 카드로 묶여 보이게 하고, 현재 월만 먹색 굵은 테두리와
  먹색 월 배지로 둔다. 표준 트랙은 회색 면, 우리 아기 트랙은 붉은 말 옅은 면(시안 B, task growth/001).
- 미구현: 또래 질문 묶음(SPEC-GROW-05) — 서버 코호트 집계가 생긴 뒤에 붙는다.
- 데이터: `src/data/timeline.ts` 의 `buildTimeline(기록, 생일)` — 0~12개월 컬럼(L1 1차 구축 범위).
  표준 트랙은 승인된 지식베이스에서 **그 달에 시작하는 접종·검진·발달 항목**, 우리 아기 트랙은 기기에 저장된
  기록이다. 수유·수면·생활·안전·대응은 월령 내내 쓰는 상시 지식이라 컬럼에 올리지 않는다(대부분 0개월에
  시작해 0개월 컬럼이 수십 줄이 된다) — 답변 근거와 홈의 팁으로 쓴다.
  기록은 **완료 처리한 항목이 시작하는 월**에 놓인다(2개월 접종을 5개월에 알려도 2개월 컬럼) —
  닫는 항목이 없으면 기록한 날의 월령. 월 특징 한 줄(headline)은 0~6개월만 목업 문구가 있다.
  미래 월 컬럼은 지금 "앞으로 채워질 기록"만 있는데, 그 자리를 또래 질문 묶음이 채우게 된다.
- 그래픽 업그레이드 경로: 하이브리드 구조 — 레이아웃·콘텐츠는 RN View 로 두고, 연결 곡선·스크롤 연동
  애니메이션 같은 커스텀 그래픽만 Skia 캔버스를 얹는다. 제스처·전환은 Reanimated(이미 설치됨).
  근거는 [app-design](../app-design/README.md)의 애니메이션 절.
