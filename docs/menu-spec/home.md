# 홈 — 지금의 단면

> 근거: [main-design](../architecture/main-design.md) · [knowledge-layers](../architecture/knowledge-layers.md)

홈은 "지금"만 다룬다. 시간축 전체는 일정 탭 챙길 것 여정(SPEC-GROW-02)의 몫이다.

**자리** — 2026-10-03 탭이 바뀌면서([decisions/012](../decisions/012-chat-first-three-tabs.md)) 홈 탭은 없어지고 SPEC 은 여러 자리로
나뉘었다. 2026-10-04 부터([decisions/017](../decisions/017-schedule-tab-and-inbox.md)) 아기 상태 한 줄(01)은 **「일정」 탭 머리**,
챙길 것(02)은 일정 탭의 달력 · 챙길 것 여정과 주간 · 월간 브리핑, 발달 포인트(03)는 월간 브리핑, 브리핑(06 · 08)은
**버디 탭 대화의 하루 첫 메시지와 일정 탭**, 알림함(07)은 버디 탭 오른쪽 위다. 아래 SPEC 의 "홈"은 이 자리를 뜻한다.

## SPEC

### SPEC-HOME-01 아기 상태 카드
```
평시 ▸ 홈 상단은 아기의 월령(생후 일수·개월)과 이 시기의 특징 한 줄을 보여줘야 한다.
평시 ▸ 월령은 저장된 생일에서 계산해야 하며 하드코딩해서는 안 된다.
```

### SPEC-HOME-02 챙길 것 추천 — 표준과 기록의 차집합
```
평시     ▸ 홈은 과거~다음 달의 표준 항목(L1 접종·검진) 중 기록(L2)이 완료 처리하지 않은 것을
          "챙길 것"으로 보여줘야 한다.
지난 항목 ▸ 지난 달 항목이 미완료면 놓침으로 단정하지 않고 "기록이 없어요 — 완료했다면 알려주세요"로
          물어야 한다. 사용자가 완료를 알리면 L2-기록이 생기고 추천에서 사라져야 한다.
다가옴   ▸ 이번 달·다음 달 항목은 시점과 함께 보여줘야 한다.
생활 항목 ▸ 접종·검진 외 생활 항목(터미타임·이유식 시작 등)도 추천에 포함하되, 설정에서
          "접종·검진만 보기"로 줄일 수 있어야 한다. (2026-10-01 Julian 결정)
분량     ▸ 한 번에 세 건까지만 보여주고 나머지는 접어 둔다. 빨간 표시가 한꺼번에 쏟아지면
          챙길 것을 알려주는 게 아니라 불안을 주는 화면이 된다.
묶음     ▸ 같은 월에 시작하는 같은 분류의 항목은 한 줄로 묶어 보여줘야 한다. 한 번의 병원 방문이
          여러 건으로 쪼개져 보여서는 안 된다. (2026-10-01 — 접종이 차수마다 한 항목이 되면서)
기간     ▸ 기간이 있는 항목(예: 6~18개월)은 기간이 끝나기 전에는 놓침으로 보지 않는다.
완료 알림 ▸ 「챙길 것」의 모든 줄(놓침·이번 달·다음 달)은 눌러서 완료를 알릴 수 있어야 한다.
          묶인 줄은 항목마다 고를 수 있어야 하고, 처음에는 모두 골라져 있어야 한다.
          일부만 고르면 고르지 않은 항목은 「챙길 것」에 남아야 한다.
          완료 날짜는 묻지 않는다. 기록의 시점은 알린 날(D+N)로 남긴다.
저장 표시 ▸ 완료를 알리면 무엇을 기록했는지 보여줘야 하고, 그 자리에서 되돌릴 수 있어야 한다.
```

### SPEC-HOME-03 이번 달 발달 포인트
```
평시 ▸ 현재 월령의 발달 이정표 요약과 이정표가 늦을 때의 상담 안내, 성장 타임라인으로 가는 길을 보여줘야 한다.
조건 ▸ 첫 이정표보다 어린 월령이면 첫 이정표가 몇 개월인지 알려줘야 한다.
```
터미타임 같은 생활 팁은 여기가 아니라 「챙길 것」의 생활 항목(SPEC-HOME-02)이 맡는다 — 같은 팁이 홈에 두 번
나오지 않게.

### SPEC-HOME-04 최근 질문 이어보기 — 폐기 (2026-10-03)
대화가 첫 화면이 되어 이어 볼 자리가 따로 필요 없다([decisions/012](../decisions/012-chat-first-three-tabs.md)).
기록에서 「대화 보기」로 그 질문 자리로 가는 길은 SPEC-MY-02 가 맡는다.

### SPEC-HOME-05 광고와 고지
```
평시 ▸ 버디 탭 바닥(입력창과 고지 아래)과 알림함 맨 아래에 배너 광고를 두고, 광고임을 표시해야 한다.
      대화 말풍선 사이에는 두지 않고, 글을 쓰는 동안(키보드가 떠 있을 때)은 숨긴다. (2026-10-04 Julian)
금지 ▸ 광고를 콘텐츠 카드처럼 보이게 하거나, 눌러야 할 버튼 가까이 두어서는 안 된다.
평시 ▸ 정보가 참고용이며 출처 기반임을 알리는 고지를 화면 하단에 두어야 한다.
```
광고를 없앤 사용자에게는 자리까지 보이지 않는다(SPEC-MY-06).

### SPEC-HOME-06 데일리 브리핑 — 안부와 오늘 하루
```
평시 ▸ 그날 처음 앱을 열면 버디 탭 대화의 첫 메시지로 그날의 브리핑을 둬야 한다. 브리핑은 그날 하루의 것이다
      (2026-10-04 Julian):
      ① 아기 안부 — 어제·그제 대화와 기록에 열 · 게움 · 덜 먹음 · 접종 · 변 · 기침 같은 일이 있었으면 이어서 묻는다
      ② 부모 안부 — 많이 보챘다 · 밤에 자주 깼다 같은 일이 있었으면 부모의 잠과 끼니를 묻는다. 없어도 일주일에 두 번쯤
      ③ 오늘 챙기면 좋을 것 — 월령에 맞는 표준(L1) 생활 팁 한두 가지, 날마다 바뀐다
      ④ 기록하면 좋을 것 — ①과 이어지는 기록 하나(열이면 체온). 일이 없으면 두지 않는다(SPEC-BABY-07)
      ⑤ 이번 주 일정 — 이번 주에 걸린 접종·검진이 있으면 한 줄
      일이 없으면 ①④는 비운다 — 지어내지 않는다. 첫머리에 인사와 그날의 한 줄(태어난 지 며칠 · 100일 · 첫돌)을 둔다.
평시 ▸ 대화에는 인사와 그날의 한 줄, 안부(눌러서 답하는 칩), 「오늘의 브리핑이 도착했어요」 요약 카드만 두고,
      「확인하러 가기」로 일정 탭의 그날에서 자세히 본다.
답   ▸ 안부에 칩으로 답하면 아기에 관한 답은 L2 기록이 되고 같은 일을 다시 묻지 않는다(constitution 3). 걱정되는 답
      (「아직 있어요」 「또 게웠어요」)은 입력창에 담아 대화로 잇는다 — 보내면 위험 신호 규칙(SPEC-ASK-02)을 거친다.
      부모에 관한 답은 아기 기록으로 남기지 않는다.
안전 ▸ 안부는 묻기만 한다 — 「괜찮을 거예요」 같은 안심 단정이나 진단·처방을 쓰지 않는다. 관련 위험 신호 L1 이 있으면
      (3개월 미만의 열 등) 출처와 함께 한 줄 붙인다. 팁은 승인된 L1 에서만 고른다(constitution 1·2).
평시 ▸ 브리핑은 기기 안에서 규칙과 문구 틀로 만든다 — 모델을 부르지 않는다(decisions/018).
평시 ▸ 정해진 시각에 알림을 보내야 한다. 알림을 누르면 앱이 열리고 그날 브리핑이 보인다.
평시 ▸ 답하지 않아도 불이익이 없어야 한다. 브리핑 때문에 독촉 알림을 더 보내지 않는다.
```
알림 시각은 온보딩에서 묻고, 건너뛰면 **오전 8시**가 기본값이다(마이에서 바꾸거나 끌 수 있다 —
2026-10-01 Julian 결정). 알림을 끄거나 허락하지 않아도 브리핑은 그날 처음 열 때 생긴다 — 알림은 여는 계기일 뿐이다
(예전 `미결:` 해소, 2026-10-03). 알림 본문에는 아기 정보를 넣지 않는다 — 잠금 화면에 보이므로.
생성 방식(1단계 온디바이스)은 [backend](../architecture/backend.md)의 능동 브리핑 절.

### SPEC-HOME-07 알림함
```
평시 ▸ 버디 탭 오른쪽 위 알림함에 브리핑(데일리 · 주간 · 월간)이 온 것과 앱의 알림(기록 요청 등, 나중에 가족 공유 신청)을
      모으고, 아직 열어 보지 않은 것의 수를 아이콘 배지로 보여야 한다. (2026-10-04 Julian)
평시 ▸ 「브리핑」 · 「알림」 둘로 나눠 보고 줄마다 요약만 둔다. 누르면 그 내용으로 간다 — 브리핑은 일정 탭의 그날,
      기록 요청은 그 카드.
읽음 ▸ 내용을 열어 보면 읽은 것이 된다 — 알림함에서 누르거나, 대화의 「확인하러 가기」, 일정 탭에서 그날을 볼 때.
금지 ▸ 배지는 앱 안에서만 보인다 — 홈 화면 아이콘에는 띄우지 않는다.
```

### SPEC-HOME-08 주간 · 월간 브리핑
```
주간 ▸ 매주 월요일, 그 주에 걸린 접종·검진(날짜 무렵)과 아직 안 한 것을 모은 주간 브리핑이 알림함과 일정 탭에 와야 한다.
월간 ▸ 월령이 바뀌는 날, 이번 달 챙길 것(접종·검진·생활 항목, SPEC-HOME-02)과 이번 달 발달 포인트(SPEC-HOME-03)를
      모은 월간 브리핑이 와야 한다.
평시 ▸ 그날 앱을 열지 않았으면 다음에 열 때 가장 최근 것 하나만 온다 — 지난 것을 몰아 보내지 않는다.
평시 ▸ 알림을 따로 더 보내지 않는다 — 아침 브리핑 알림과 알림함 배지로 안다.
```

## HOW (현재 구현)

- 화면: 「일정」 탭(`src/app/(tabs)/schedule.tsx`, growth.md HOW) — 머리에 태어난 지 N일 · 만 N개월 · 월 한 줄(SPEC-HOME-01),
  달력 · 고른 날 · 챙길 것 여정이 챙길 것(SPEC-HOME-02)을 보인다. 줄 모양은 브리핑과 같은 `src/components/todo-row.tsx`
  (다가오는 것은 D-day, 지금·놓친 것은 단추 — 단추가 있는 줄은 단추만 누른다).
  추천은 `src/data/timeline.ts` 의 `getGaps(월령)`(covers 차집합)을 `groupGaps()` 로 묶어 만든다. 묶음 키는 상태(놓침·지금·다음 달)·
  시작 월·분류이고, 같은 차수끼리 이름을 이어 붙인다(「DTaP·폴리오·Hib·폐렴구균·로타바이러스 1차」).
  표준(L1)은 승인된 지식베이스(접종·검진, 2026-10-01~), 기록(L2)은 기기에 저장된 것이다
  (`src/data/records.ts` · `records-context.tsx`, task/home/001).
- 발달 포인트(SPEC-HOME-03)는 월간 브리핑으로 옮긴다(task home/009). 첫 이정표보다 어리면 「첫 발달 이정표는 2개월이에요」.
- 완료 알림: 줄을 누르면 `src/components/mark-done-sheet.tsx` 가 항목을 모두 고른 채 열린다(흐름은
  `src/hooks/use-mark-done.tsx` — 일정 탭의 고른 날 · 여정이 같이 쓴다).
  저장하면 `기록` 하나가 생기고(`covers` = 고른 항목 id, `whenLabel` = "D+N에 알림") 카드 위에
  「…로 기록했어요 · 되돌리기」가 뜬다. 되돌리기는 그 기록을 지운다.
- 생활 항목(task home/003): 생활·수유·수면·안전 분류의 L1 이 기간 안이거나 다음 달에 시작하면 「챙길 것」에
  오른다. 마감이 없어 놓침으로 묻지 않고, 줄 이름은 「안전한 잠 5가지」처럼 분류와 개수, 단추는 「확인」이다.
  같은 상태면 접종·검진이 먼저 나온다. 마이 「설정」의 스위치를 끄면 접종·검진만 보인다
  (settings `todo_schedule_only`, `src/data/preferences-context.tsx`).
- 브리핑(task home/004): `src/hooks/use-daily-briefing.ts` 가 그날 첫 화면에서 `src/data/briefing.ts` 의
  `buildBriefing()` 으로 만들어 `chat_message` 에 `meta.type = 'briefing'` 으로 넣는다(모델을 부르지 않는다).
  했는지는 볼 때마다 기록(covers)으로 다시 센다. 대화 속 요약은 `src/components/briefing-card.tsx` 의 `BriefingSummary` —
  「확인하러 가기」는 일정 탭의 그날(`scheduleDayHref()`)로 가고 알림함의 그날 줄을 읽음으로 한다. 자세한 카드
  (`BriefingCard`)는 일정 탭 고른 날에. 하루 기록은 우리 아기 탭(baby.md HOW, task baby/003). 알림은 `src/data/notifications.ts`
  (expo-notifications 로컬, 매일, 식별자 `morning-briefing`) — 시각은 settings `briefing_time`(`HH:MM` · `off`, 없으면 08:00),
  앱을 열 때마다 다시 건다
- 알림함(task home/007): 저장은 기기 `inbox_card`(`db.ts` · 웹은 `db.web.ts` localStorage), 모양은 `src/data/inbox.ts`,
  화면들이 함께 보는 자리는 `inbox-context.tsx`(새것부터 · 읽지 않은 수 · 넣기 · 읽음 · 그날 읽음). 데일리 브리핑을 만들 때
  `daily-<날짜>` 줄(요약은 `briefingSummary()`), 기록 요청이 저절로 뜰 때 `nudge-<물을 날>` 줄(카드를 닫으면 읽음 — 카드를 끄고
  알림만 둔 사람도 한 번 비었을 때 한 줄). 알림함이 생기기 전의 지난 브리핑은 읽은 줄로 옮겼다.
  화면 `src/app/inbox.tsx` — 「브리핑」 · 「알림」(새 것 수), 줄마다 아이콘 · 제목 · 요약 · 언제 · 새 것 점, 「모두 읽음」, 맨 아래 배너.
  누르면 브리핑은 일정 탭의 그날, 기록 요청은 `openRecordNudge()` 로 카드. 일정 탭에서 그날을 보면 그날 줄이 읽음이 된다.
  배지는 버디 탭 오른쪽 위 `IconButton badge`(읽지 않은 수)
