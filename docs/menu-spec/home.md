# 홈 — 지금의 단면

> 근거: [main-design](../architecture/main-design.md) · [knowledge-layers](../architecture/knowledge-layers.md)

홈은 "지금"만 다룬다. 시간축 전체는 성장 탭의 몫이다.

## SPEC

### SPEC-HOME-01 아기 상태 카드
```
평시 ▸ 홈 상단은 아기의 월령(생후 일수·개월)과 이 시기의 특징 한 줄을 보여줘야 한다.
평시 ▸ 월령은 저장된 생일에서 계산해야 하며 하드코딩해서는 안 된다.
```

### SPEC-HOME-02 챙길 것 추천 — 표준과 기록의 차집합
```
평시     ▸ 홈은 과거~다음 달의 표준 항목(L1 접종·검진) 중 기록(L2)이 완료 처리하지 않은 것을
          "챙길 것"으로 보여줘야 한다.
지난 항목 ▸ 지난 달 항목이 미완료면 놓침으로 단정하지 않고 "기록이 없어요 — 완료했다면 알려주세요"로
          물어야 한다. 사용자가 완료를 알리면 L2-기록이 생기고 추천에서 사라져야 한다.
다가옴   ▸ 이번 달·다음 달 항목은 시점과 함께 보여줘야 한다.
생활 항목 ▸ 접종·검진 외 생활 항목(터미타임·이유식 시작 등)도 추천에 포함하되, 설정에서
          "접종·검진만 보기"로 줄일 수 있어야 한다. (2026-10-01 Julian 결정)
```

### SPEC-HOME-03 이번 달 발달 포인트
```
평시 ▸ 현재 월령의 발달 이정표 요약(2~3줄)과 성장 타임라인으로 가는 길을 제공해야 한다.
```

### SPEC-HOME-04 최근 질문 이어보기
```
평시 ▸ 최근 질문 1~2개를 보여주고 누르면 물어보기 탭의 해당 대화로 이어져야 한다.
```

### SPEC-HOME-05 광고와 고지
```
평시 ▸ 홈 콘텐츠 하단에 배너 광고 1개를 두고, 광고임을 표시해야 한다.
평시 ▸ 정보가 참고용이며 출처 기반임을 알리는 고지를 화면 하단에 두어야 한다.
```

### SPEC-HOME-06 아침 브리핑 카드와 인박스
```
평시 ▸ 매일 아침 정해진 시간에, 기록(L2)과 표준(L1)을 분석한 브리핑 카드를 만들어 푸시로
      보내고 홈의 인박스에 쌓아야 한다. 카드는 ①오늘 할 일 ②챙기지 못한 것
      ③아기 상태 확인(컨디션·수유 같은 가벼운 입력 요청)으로 구성된다.
평시 ▸ 카드에서 할 일을 완료 처리하거나 상태 확인에 답하면 L2 기록이 생겨야 하고,
      챙길 것 추천(SPEC-HOME-02)과 서로 어긋나지 않아야 한다.
평시 ▸ 답하지 않아도 불이익이 없어야 한다. 독촉 알림을 추가로 보내지 않는다.
```
발송 시각은 온보딩에서 묻고, 건너뛰면 **오전 8시**가 기본값이다(설정에서 변경 가능 —
2026-10-01 Julian 결정). 온보딩 문항 추가는 브리핑 도입 task 에서 함께 구현한다.
`미결:` 푸시를 끈 사용자의 인박스 동작 — 브리핑 task 에서.
생성 방식(1단계 온디바이스)은 [backend](../architecture/backend.md)의 능동 브리핑 절.

## HOW (현재 구현)

- 화면: `src/app/index.tsx`. 추천은 `src/data/timeline.ts` 의 `getGaps()`(covers 차집합)로 계산 — 지금은 목업 데이터.
- 광고: `src/components/ad-banner.tsx` placeholder.
- 미구현: 생일 기반 실계산(SPEC-HOME-01 둘째 줄 — task/my/001), 완료 알림 → L2 생성 흐름, 질문 이어보기 연결.
