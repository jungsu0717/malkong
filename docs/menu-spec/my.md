# 마이 — 온보딩 · 프로필 · 고지

> 근거: [main-design](../architecture/main-design.md)

## SPEC

### SPEC-MY-01 온보딩은 생일 하나
```
평시 ▸ 처음 실행하면 아기 생일(선택적으로 이름) 입력만으로 앱을 시작할 수 있어야 한다.
평시 ▸ 생일이 저장되면 모든 화면의 월령·일수·표준 일정이 그 값에서 계산되어야 한다.
금지 ▸ 온보딩에서 생일 외의 정보를 필수로 요구해서는 안 된다. 나머지는 대화에서 쌓는다.
```

### SPEC-MY-02 아기 프로필
```
평시 ▸ 저장된 아기 정보(생일·이름·L2 기록)를 보고 고칠 수 있어야 한다.
정정 ▸ 기록을 고치면 그것을 근거로 한 홈 추천·답변 컨텍스트가 따라 바뀌어야 한다.
다음 ▸ 프로필과 기록에 사진을 붙일 수 있어야 한다. 사진은 기기 안에 저장한다 — 가족 공유를 켜면
      그 동기화 대상(SPEC-MY-05)에 함께 들어간다.
```
사진을 어디에 두는지는 [backend](../architecture/backend.md) 「사진·파일 — 어디에 두는가」.

### SPEC-MY-03 고지와 약관
```
평시 ▸ 이용약관 · 개인정보 처리방침 · 의학 정보 출처와 한계 고지에 항상 접근할 수 있어야 한다.
평시 ▸ L2 데이터가 어디에 저장되는지(초기: 기기 안)를 개인정보 항목에서 알 수 있어야 한다.
```

### SPEC-MY-04 로그인 (나중)
```
평시 ▸ 로그인 없이도 핵심 기능(질문·기록·타임라인)을 쓸 수 있어야 한다.
나중 ▸ 로그인은 가족 공유·기기 이전이 필요해질 때 도입한다. 도입 전에는 유도 카드만 둔다.
```

### SPEC-MY-06 광고 없이 쓰기 (구매)
```
평시     ▸ 마이 탭에서 한 번 결제해 광고를 없앨 수 있어야 한다.
구매 후   ▸ 배너와 전면 광고가 모두 사라져야 하고, 광고가 있던 자리도 비어 보이지 않아야 한다.
복원     ▸ 앱을 다시 설치해도 구매를 복원할 수 있어야 한다 — 구매 사실의 정본은 스토어다.
금지     ▸ 광고를 없애도 질문 한도·답변 품질은 달라지지 않는다. 광고 제거는 광고만 없앤다.
```
한도 면제는 운영자(가족) 기기에만 해당한다([backend](../architecture/backend.md) 운영자 절) —
광고 제거 구매와 섞지 않는다.

### SPEC-MY-05 가족 공유 (나중)
```
나중 ▸ 한 아기를 여러 양육자가 함께 볼 수 있어야 한다. 동기화 대상은 아기 프로필과 L2 기록으로
      한정하고, 챗 이력은 각자의 기기에 남는다. 무엇이 서버로 올라가는지 사용자에게 보여야 한다.
```
서버 구성은 [backend](../architecture/backend.md)를 따른다.

## HOW (현재 구현)

- 온보딩: `src/app/onboarding.tsx` — 두 걸음. ① 생일(년·월·일 숫자 입력)과 이름(선택) ② 아침 브리핑 알림 시각
  (오전 7~10시, 기본 8시 · 「알림 받기」면 허락을 묻는다 · 「나중에 할게요」여도 시각은 남는다, SPEC-HOME-06).
  알림이 없는 웹 미리보기는 ②를 건너뛴다. 저장된 생일이
  없으면 루트 레이아웃의 게이트가 이 화면으로 보낸다. `?edit=1` 로 열면 프로필 수정 화면이 된다(②는 없다).
  네이티브 날짜 피커 대신 숫자 입력을 쓰는 이유는 웹 미리보기까지 같은 화면으로 확인하기 위해서다.
- 저장: `src/data/baby.ts`(월령 계산·저장 API) + `src/data/db.ts`·`db.web.ts`(기기 저장소).
  **월령은 저장하지 않고 생일에서 매번 계산한다** — `src/data/baby-context.tsx` 가 화면들에 공급하므로
  생일을 고치면 모든 탭이 바로 따라 바뀐다.
- 마이 화면: `src/app/(tabs)/my.tsx`(시안 B, task my/005) — 프로필 카드(누르면 수정) · 우리 아기 기록 ·
  알림(아침 브리핑 켜고 끄기 · 시각 · 기록이 비면 알림 · 기록이 비면 카드(SPEC-BABY-07), 휴대폰에서 알림이 꺼져 있으면
  「설정 열기」) · 설정(생활 항목) · 광고 없이 쓰기 ·
  가족과 함께 보기(준비 중) · 도움말 · 약관 · 버전(길게 누르면 기기 키).
- 기록 보기·고치기(task my/002): `src/app/records.tsx`(`src/components/baby/records-view.tsx`) — 우리 아기 탭의
  「기록 전체 보기」와 마이의 「우리 아기 기록」에서 들어간다(task baby/001).
  최근 것부터 보이고 고치기·지우기·대화 보기(그 기록이 나온 질문 자리로), 직접 적기. 고친 기록은 낡음 표시가
  지워진다. 바뀐 기록은 records-context 를 거쳐 홈 추천과 답변에 보내는 기록에 바로 반영된다.
- 약관·고지(task my/003): 본문 정본은 `src/data/legal.ts`(이용약관 · 개인정보 처리방침 · 의학 정보 출처와 한계 고지 ·
  자주 묻는 질문), 화면은 `src/app/legal/[doc].tsx`. 지금은 **초안** — 운영자 이름·문의 이메일·시행일이 비어 있고
  (`OPERATOR`), 출시 전에 Julian 이 채우고 검토한 뒤 `DRAFT` 를 내린다. 개인정보 처리방침은 기기 안 저장(SPEC-MY-03
  둘째 줄), 질문 때 보내는 것, 서버에 남는 것, 광고·결제, 위탁·국외 이전을 앱이 실제로 하는 대로 적는다 — 앱이 바뀌면 같이 고친다.
- 로그인 유도 카드는 「가족과 함께 보기 · 준비 중」 안내만 둔다(누를 단추 없음).
- 광고 없이 쓰기(task my/004): `src/components/no-ads-card.tsx` + `src/data/purchases.ts`(RevenueCat, 웹은
  `purchases.web.ts`). entitlement `no_ads`, 현재 offering 의 lifetime 꾸러미. 구매·복원·부팅 때 스토어에 물은 결과를
  settings `ads_removed` 사본에 맞춘다(환불이면 광고가 다시 나온다). 광고 표시는 서버 자격(운영자 기기)과 구매를 따로 들고
  둘 다 허락할 때만이다(entitlements-context). 공개 SDK 키 `EXPO_PUBLIC_REVENUECAT_{IOS,ANDROID}_KEY` 가 없으면 「준비 중」.
- 미구현: 공지사항, 로그인(SPEC-MY-04), 가족 공유(SPEC-MY-05), 사진(SPEC-MY-02 다음).
