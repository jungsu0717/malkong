# 마이 — 온보딩 · 프로필 · 고지

> 근거: [main-design](../architecture/main-design.md)

## SPEC

### SPEC-MY-01 온보딩은 생일 하나
```
평시 ▸ 처음 실행하면 아기 생일(선택적으로 이름) 입력만으로 앱을 시작할 수 있어야 한다.
평시 ▸ 생일이 저장되면 모든 화면의 월령·일수·표준 일정이 그 값에서 계산되어야 한다.
금지 ▸ 온보딩에서 생일 외의 정보를 필수로 요구해서는 안 된다. 나머지는 대화에서 쌓는다.
```

### SPEC-MY-02 아기 프로필
```
평시 ▸ 저장된 아기 정보(생일·이름·L2 기록)를 보고 고칠 수 있어야 한다.
정정 ▸ 기록을 고치면 그것을 근거로 한 홈 추천·답변 컨텍스트가 따라 바뀌어야 한다.
```

### SPEC-MY-03 고지와 약관
```
평시 ▸ 이용약관 · 개인정보 처리방침 · 의학 정보 출처와 한계 고지에 항상 접근할 수 있어야 한다.
평시 ▸ L2 데이터가 어디에 저장되는지(초기: 기기 안)를 개인정보 항목에서 알 수 있어야 한다.
```

### SPEC-MY-04 로그인 (나중)
```
평시 ▸ 로그인 없이도 핵심 기능(질문·기록·타임라인)을 쓸 수 있어야 한다.
나중 ▸ 로그인은 가족 공유·기기 이전이 필요해질 때 도입한다. 도입 전에는 유도 카드만 둔다.
```

### SPEC-MY-05 가족 공유 (나중)
```
나중 ▸ 한 아기를 여러 양육자가 함께 볼 수 있어야 한다. 동기화 대상은 아기 프로필과 L2 기록으로
      한정하고, 챗 이력은 각자의 기기에 남는다. 무엇이 서버로 올라가는지 사용자에게 보여야 한다.
```
서버 구성은 [backend](../architecture/backend.md)를 따른다.

## HOW (현재 구현)

- 화면: `src/app/my.tsx` — 로그인 유도 카드·메뉴 리스트 정적 시안.
- 미구현: 온보딩 화면(생일 입력 → 저장 → BABY 실계산), 프로필 편집, 약관 본문.
- 저장소: 초기엔 기기 저장(후보: expo-sqlite 또는 AsyncStorage — task 에서 결정).
