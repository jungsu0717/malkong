# 물어보기 — 말콩이와의 대화

> 근거: [main-design](../architecture/main-design.md) · [knowledge-layers](../architecture/knowledge-layers.md)

agent 의 이름은 **말콩이**다. 답변과 기록 수집이 이 한 화면에서 일어난다.

## SPEC

### SPEC-ASK-01 월령 맞춤 답변과 출처
```
평시 ▸ 말콩이는 저장된 아기의 월령과 L2 기록을 반영해 답해야 한다.
평시 ▸ 답변에는 근거가 된 L1 지식의 출처를 함께 보여줘야 한다.
금지 ▸ 출처 화이트리스트 밖의 지식으로 의료·발달 관련 단정을 만들어서는 안 된다.
```

### SPEC-ASK-02 위험 신호 고정 응답
```
조건 위반 ▸ 질문에 위험 신호(3개월 미만 발열, 탈수, 호흡곤란, 경련, 의식 저하 등)가 담기면,
          말콩이는 일반 답변보다 먼저 병원·119 안내를 내야 한다.
평시     ▸ 모든 답변 화면에는 "참고용이며 응급 상황은 병원·119" 고지가 보여야 한다.
```

### SPEC-ASK-03 답변 전 기록 수집
```
조건    ▸ 답변에 필요한 아기 정보(수유 텀·양, 몸무게, 체온 등)가 없으면, 말콩이는 답하기 전에
         그것을 물어야 한다. 되묻기는 한 번에 1~2개를 넘지 않아야 한다.
저장    ▸ 사용자의 답은 L2(기록 또는 요약)로 저장해야 하며, 저장된 사실을 답변과 함께 표시해야 한다.
재질문 금지 ▸ 이미 저장된 정보를 다시 물어서는 안 된다. 오래된 값이 필요하면 "지난달 기준 6.4kg 인데
         지금도 비슷한가요"처럼 갱신 확인으로 물어야 한다.
회피    ▸ "잘 모르겠어요"를 항상 고를 수 있어야 하고, 그 경우 일반 기준으로 답하되 그렇게 답했음을 밝힌다.
```

### SPEC-ASK-04 빠른 입력
```
평시 ▸ 되묻기에는 두드려서 답할 수 있는 선택지(칩)를 함께 제공해야 한다. 타이핑은 항상 가능해야 한다.
```

### SPEC-ASK-05 처리 현황 표시
```
평시 ▸ 질문을 보낸 뒤 답변이 올 때까지, 말콩이는 지금 무엇을 하는지("우리 아기 기록 확인",
      "표준 지식 찾기" 같은 한글 라벨)와 경과 시간을 질문 바로 아래에 보여줘야 한다.
금지 ▸ 처리 현황에 내부 이름(도구·API·모델명)을 그대로 노출해서는 안 된다.
평시 ▸ 답변이 오면 처리 현황은 "N단계 확인했어요" 한 줄로 접혀야 하고, 누르면 각 단계와
      한 줄 결과(예: "표준 지식 3건")를 다시 볼 수 있어야 한다.
```

### SPEC-ASK-06 답변 피드백
```
평시 ▸ 모든 답변에는 좋아요/별로예요를 누를 수 있어야 하고, 의견 글은 선택 입력이어야 한다.
평시 ▸ 피드백은 강요하지 않는다 — 피드백 없이도 모든 기능을 쓸 수 있어야 한다.
저장 ▸ 피드백은 서버로 보내 답변 품질 개선(캐시 승격·프롬프트 조정)에 쓴다. 개인 식별과 분리해 저장한다.
```

### SPEC-ASK-07 어디서든 질문 — 플로팅 버튼 — 폐기 (2026-10-03)
대화가 첫 탭이 되어 어느 화면에서든 한 번 누르면 닿는다([decisions/012](../decisions/012-chat-first-three-tabs.md)).
떠 있는 단추가 「우리 아기」의 카드와 배너를 가리던 문제도 함께 사라진다.

### SPEC-ASK-08 답변 수위 — 아는 만큼만, 아는 티를 내며
```
사실 조회 ▸ 접종·검진 일정처럼 공공 기준에 답이 정해진 질문은 그 기준과 출처를 그대로 보여줘야 한다.
일반 정보 ▸ L1 에 근거가 없으면 "일반적으로는" 임을 밝히고 낮은 확신으로 답해야 한다.
          근거가 없다는 사실을 숨기고 단정해서는 안 된다.
판단 요구 ▸ "우리 아기가 괜찮은지" 처럼 개별 판단을 요구하는 질문에는 판단을 내리지 않고,
          무엇을 살펴보면 좋은지와 함께 진료를 권해야 한다.
```
세 수위를 구분하는 이유는 [constitution](../constitution.md) 원칙 2(의료 경계)를 코드가 지키게 하기
위해서다. 전문가 감수를 받기 전까지 특히 이 구분이 안전장치 노릇을 한다.

### SPEC-ASK-09 혼자가 아니라는 신호
```
평시     ▸ 답변 아래에 같은 월령 밴드에서 같은 주제를 물은 사람 수를 한 줄로 보여줘야 한다.
조건 위반 ▸ 표본이 기준(k)보다 작으면 수를 보여주지 않는다.
금지     ▸ 누가 물었는지 짐작할 수 있는 것(질문 원문·시각·프로필)을 함께 보여줘서는 안 된다.
```
집계는 [backend](../architecture/backend.md) 코호트 절의 것을 그대로 쓴다 — 질문이 어차피 서버를
거치므로 추가 전송도, 추가 비용도 없다.

### SPEC-ASK-10 대화 이력 — 하나로 이어지는 타임라인
```
평시 ▸ 물어보기의 대화는 대화방으로 나누지 않고 하나의 타임라인으로 이어져야 하며,
      날짜가 바뀌는 자리마다 날짜가 보여야 한다.
다음 ▸ 지난 대화를 검색어와 날짜로 찾을 수 있어야 한다.
다음 ▸ 질문과 답 한 쌍을 보관함에 담을 수 있어야 하고, 담은 항목에는 그때의 날짜와 생후 일수(D+N)가
      함께 남아야 한다.
나중 ▸ 다둥이를 지원하면 아기마다 타임라인을 나눈다.
```
대화 이력을 어디에 두는지(기기 안에만)는 [backend](../architecture/backend.md) 「DB — 두 단계」가 정본이다.
대화방으로 나누지 않는 이유는 [decisions/009](../decisions/009-single-timeline.md).

### SPEC-ASK-11 사진으로 묻기 (나중)
```
나중     ▸ 질문에 사진을 붙여 물을 수 있어야 한다. 사진을 모델에 보내기 전에, 보낼 때마다
          사용자에게 확인을 받아야 한다. 한 번의 확인으로 다음 사진까지 보내서는 안 된다.
위험 신호 ▸ 사진을 붙인 질문도 글은 먼저 위험 신호 규칙 필터(SPEC-ASK-02)를 거쳐야 한다.
금지     ▸ 사진을 근거로 위험 신호가 아니라고 단정해서는 안 된다.
절약 모드 ▸ 일일 한도를 넘어 절약 모드일 때는 사진을 받지 않는다. 이때도 글에 담긴 위험 신호에는
          고정 응답을 내야 한다.
판단 요구 ▸ 사진으로 판단을 요구하는 질문(발진·변 색 등)도 SPEC-ASK-08 의 판단 요구 수위를 따른다 —
          사진이 있다고 진단에 가까워지지 않는다.
```
`미결:` 사진에 담긴 위험 신호(청색증·혈변 등)를 어떻게 걸러낼지 — 규칙 필터는 글만 본다. 위험 신호 판별을
모델에 맡기지 않는다는 원칙([backend](../architecture/backend.md) 라우팅)과 함께 이 기능의 task 에서 정한다.
사진을 어디에 두는지는 backend 「사진·파일 — 어디에 두는가」.

## HOW — 대화 상세 설계

파이프라인 전체는 [backend](../architecture/backend.md), API 형태는 [api-contract](../architecture/api-contract.md)가 정본이다.

### 되묻기 판단표 (SPEC-ASK-03 의 구현 기준)

질문 주제를 분류해, 그 주제에 필요한 L2 가 없을 때만 묻는다. 최대 2개.

| 질문 주제 | 필요한 기록 (없으면 묻는다) |
|---|---|
| 수유량·수유 거부 | 수유 방식(모유·분유·혼합) · 평소 텀과 양 |
| 수면 | 밤중 수유 횟수 · 재우는 방식 |
| 발열·아파 보임 | 체온(지금 잰 값) · 접종 직후 여부 |
| 성장(몸무게·키) | 최근 측정값과 측정일 |
| 이유식 | 시작 여부 · 알레르기 의심 이력 |
| 그 외 일반 | 되묻지 않고 월령 기준으로 답한다 |

### L2 추출 규칙

- 되묻기에 대한 답 → 즉시 **기록**으로 저장.
- 자유 발화에 섞인 사실("어제 재보니 6.4kg") → **기록**으로 자동 저장하되, 답변 밑에 「기록됨」 칩을
  보여주고 탭하면 수정·삭제할 수 있다(자동이되 투명하게).
- 답변 과정에서 생긴 해석("급성장기로 보임") → **요약**으로 저장하고 시점(when)을 붙인다.

### 위험 신호 사전 (SPEC-ASK-02 규칙 필터)

범주마다 기준 수치는 L1 의 red_flag 항목(`대응` 분류, 2026-10-02 승인)이 정본이다 — 여기 다시 적지 않는다.
매칭되면 LLM 을 부르지 않고 고정 응답(병원·119 안내 + 해당 L1 항목)을 낸다.

| 범주 | L1 항목 |
|---|---|
| 어린 월령의 발열 | `k-warn-0001` (3개월 미만) · `k-warn-0002` (12주 미만 모든 열) |
| 지속 고열 · 재발·악화 | `k-warn-0002` |
| 호흡곤란 · 청색증 | `k-warn-0003` |
| 경련 | `k-warn-0004` |
| 의식 처짐 | `k-warn-0005` |
| 탈수 징후 | `k-warn-0006` · `k-warn-0008` |
| 심한 구토 · 혈변 | `k-warn-0008` |
| 낙상 · 머리 부딪힘 후 이상 행동 | `k-warn-0007` |

출처는 모두 미국 CDC 다. 국가건강정보포털(국내 기준)은 원문을 찾지 못해 쓰지 않았고, 국내 출처 보강은
task/common/001 6단계에 있다.
문장 매칭 규칙(어떤 말이 어느 범주인가)은 서버 `app/domain/ask/redflag.py` 에 있고, 잡아야 할 말과 잡으면
안 되는 말의 표가 `tests/test_redflag.py` 다 — 규칙을 고치면 표부터 고친다. 규칙의 태도:

- 놓치는 쪽보다 더 잡는 쪽으로 기운다. 잘못 잡으면 진료 권유로 끝나지만, 놓치면 위험하다
- 기준 수치는 L1 항목 그대로다. 증상이 없다는 말("경련은 없었어요")에는 걸리지 않는다
- 머리를 부딪힌 것만으로는 걸지 않는다. 위험 징후가 함께 있을 때 건다 — 징후 없는 질문에는 L1 검색이
  `k-warn-0007` 을 건네 모델이 살펴볼 징후를 안내한다
- 모델이 없어도, 한도를 넘었어도 이 응답은 나간다(backend 일일 한도 절)

규칙만으로는 처음 보는 말투의 절반만 잡아서(2차 검증 51%), 놓친 것은 모델이 답하면서 범주를 표시하고
서버가 고정 안내로 바꾼다 — 두 겹([decisions/010](../decisions/010-redflag-two-layers.md)).
`미결:` 두 겹 판별의 구현과 Julian 승인 — task common/004 에서 이어 한다.

### 프롬프트 골격 (서버 소유)

- system: 말콩이 정체성 + constitution 제약(화이트리스트 밖 의료 단정 금지 · 진단/처방 금지 ·
  참고 고지) + **답변 수위 셋(SPEC-ASK-08)** + 출력 형식(답변, 인용한 L1 id 목록, 기록 후보, 되묻기 요청)
- context: 아기(월령·관련 L2 요약) + 검색된 L1 조각(id 포함 — **답변은 전달된 id 만 인용할 수 있다**)
- L1 에 근거가 없으면 "일반적인 정보로는" 임을 밝히고 낮은 확신으로 답한다

### L1 검색 — 무엇을 모델에 건네는가 (서버 `app/domain/ask/retrieval.py`)

색인 없이 규칙과 글자 겹침으로 고른다(최대 8개). 순서는 ① 백신 이름이 나오면 그 백신의 모든 차수(차수가
나오면 그 차수만) ② 질문에 나온 월령("6개월", "돌", "다음 접종")이나 아기 월령의 항목 가운데 질문의 분류
낱말(접종·수유·수면…)에 맞는 것 ③ 접종·검진은 그 달 것을 모두, 그 밖에는 L1 전체에서 드문 두 글자 조합이
많이 겹치는 순서로. 꿀·이불·카시트처럼 뜻이 분명한 주제어가 질문과 항목에 함께 나오면 바로 고르고,
발달을 물으면 그 달·다음 이정표와 조기 상담 안내를 늘 함께 건넨다. 분류 낱말이 하나도 없으면 아무것도
건네지 않는다 — 억지로 붙인 근거는 근거가 아니다. 모델 비교 질문 세트(`server/eval/questions.json`)의
사실 질문 정답을 모두 다시 찾아내는지가 시험이다(`tests/test_retrieval.py`).

### 답 검사 — 서버가 모델의 답을 그대로 내보내지 않는다 (서버 `app/domain/ask/service.py`)

- 건네지 않은 id 를 인용하면 그 id 는 버린다. 사실 수위인데 남는 인용이 없으면 한 번 다시 생성하고,
  그래도 없으면 503 `MODEL_UNAVAILABLE`
- 판단 수위에 안심 표현(괜찮다·정상이다·문제없다·걱정 말라)이 있으면 한 번 다시 생성하고, 그래도
  있으면 판단하지 않는 고정 문장("판단해 드릴 수는 없어요… 진료를 받아 보세요")으로 끝낸다.
  "아기마다 차이가 있어요"는 판정이 아니라 사실이라 잡지 않는다([decisions/011](../decisions/011-useful-general-answers.md))
- 수위를 고르는 기준은 프롬프트가 정한다([decisions/011](../decisions/011-useful-general-answers.md)) — 일반 답은
  흔히 알려진 기준을 범위로 말하고 집에서 해 볼 방법을 알려 준다. 판단은 "괜찮은가요·정상인가요"처럼
  판정을 직접 구하는 질문만이고, 그때도 흔한 모습·살펴볼 것·진료가 필요한 기준을 말한다. 진료 권유는
  그 기준을 말할 때 끝에 한 번만
- 근거 없는 일반 답에 "일반적"이 없으면 서버가 앞에 붙인다
- 무료 티어(`MALKONG_LLM_PAID_TIER` 꺼짐)나 절약 모드에서는 아기 기록을 모델에 보내지 않고 `eco: true`.
  이때는 되묻지 않는다 — 칩으로 답해도 그 기록을 못 보내니 같은 질문이 되풀이되기 때문이다(SPEC-ASK-03)
- 되묻기는 다듬어서 내보낸다 — 빈 선택지는 버리고, "잘 모르겠어요"가 없으면 붙이고, 질문·기록 이름이
  비었거나 선택지가 2~4개가 아니면 다시 생성한다
- 모델 한 번에 기다리는 시간은 `MALKONG_LLM_TIMEOUT_S`(기본 20초). 넘으면 그 시도는 실패다

### 처리 현황 블록 (SPEC-ASK-05 의 구현)

이식 원본은 selvas 통합 chat(neuro-frontend `packages/chat`)의 두 부품이다:

- `ThinkingIndicator` — 생각 중 Orb(상태 모션) 옆에 대기 문구가 **3.2초 간격으로 순환**하며
  shimmer 로 반짝인다. 서버가 라벨을 보내면 순환 대신 그 라벨을 보여준다. 완료되면 같은 Orb 를
  정지시켜 시각적 연속성을 유지한다.
- `ChatTrace` — 접이식 "생각 과정" 목록. 헤더는 기본 접힘 + 라이브 라벨이고, 사용자가 열면
  단계마다 완료 체크/진행 점 + 제목 + 한 줄 요약, 단계별 상세는 다시 개별로 펼친다.
  완료 요약 형식은 "생각 과정 · N단계 완료".

말콩에서는 이 둘을 한 블록으로 합쳐 질문 아래(답변이 올 자리)에 둔다. Orb 자리는 말콩이
캐릭터가 맡는다(웹 전용 thinking-orbs 패키지는 RN 에서 못 쓰므로 자체 모션). 대기 문구는
말콩이 톤으로 바꿔 쓴다 — "우리 아기 기록을 살펴보고 있어요…", "표준 육아 지식을 찾아보고
있어요…", "출처를 확인하고 있어요…", "답변을 가지런히 정리하고 있어요…".

파이프라인 단계([backend](../architecture/backend.md) 라우팅 폭포)를 표시 라벨로 옮기는 표:

| 내부 단계 | 표시 라벨 | 한 줄 결과 예 |
|---|---|---|
| L2 조회 | 우리 아기 기록 확인 | 수유 기록 2건 |
| L1 검색 | 표준 지식 찾기 | 질병관리청 외 3건 |
| 모델 합성(③) | 답변 정리 | — |
| 위험 신호(①) | 표시하지 않음 — 즉시 고정 응답이라 현황 없이 바로 답한다 | |

- v0 API 는 단건 JSON이라([api-contract](../architecture/api-contract.md), 스트리밍 미결) 서버가
  단계를 실시간으로 보내지 않는다. 그동안은 위 대기 문구 4종을 3.2초 간격으로 순환시킨다.
  SSE 도입 시 서버 라벨·단계 신호로 교체하되 표시 규칙은 그대로 둔다(원본과 같은 계약).
- 부품: `src/components/thinking-status.tsx`. 진행 중 = 말콩이 모션 + 순환 문구 + 경과 초,
  완료 = 정지 + "N단계 확인했어요" 접힘(누르면 단계 목록 — 체크 + 제목 + 한 줄 요약).

### 한도 표시 (backend 일일 한도 절의 화면 쪽 규칙)

- 잔여 횟수는 평소에 보여주지 않는다 — **3회 이하로 내려가면** 머리 오른쪽에 조용히 표시한다.
- 소진 후 전송하면 두 선택지를 준다: "오늘 정밀 답변 10회를 다 썼어요. **광고 1편을 보면 우리 아기
  기록을 반영한 정밀 답변 1회가 충전**돼요(오늘 3편까지). 아니면 **지금 바로 일반 기준으로** 답해드릴
  수 있어요." → [광고 보고 정밀 답변] / [일반 기준으로 바로 답변]. 되묻기 진행 중이던 대화는 끊지 않는다.
- 절약 모드 답변에는 「일반 기준 · 기록 없이」 표시가 붙는다. 기록을 반영한 답에는 「우리 아기 기록 N건 참고」가 붙는다.
- 위험 신호 응답은 한도와 무관하게 항상 나간다 — 소진 상태에서도 응급 질문은 막히지 않는다.

### 현재 구현

- 화면: `src/app/(tabs)/index.tsx`(말콩 탭, 첫 화면) — 날짜 구분선이 있는 하나의 타임라인 + 빠른 질문 칩 + 입력창.
  모양은 시안 B(task ask/005): 질문은 오른쪽 회색 말풍선, 답은 말풍선 없는 본문과 아래 표시 한 줄(기록 참고 ·
  수위) · 출처 · 「기록했어요」 줄 · 피드백. 줄들은 `src/components/chat-bubbles.tsx`
- 흐름: `src/hooks/use-malkong.ts` — `POST /v1/ask`(`src/data/api.ts`)를 부르고, 질문과 답을
  `chat_message` 에 저장한다(`src/data/chat.ts` · `chat-context.tsx`). 되묻기에 고른 답은 L2 기록이 되고 원래
  질문을 다시 보낸다. "잘 모르겠어요"는 `mode: "eco"` 로. 답변의 기록 제안은 자동 저장해 「기록됨」으로 보인다
- 처리 현황: 기다리는 동안 순환 문구 + 경과 초. 답이 오면 응답으로 만든 한 줄 결과(기록 N건 · 출처 이름 외 N건 ·
  일반 기준이면 기록을 쓰지 않았다는 말)로 접힌다. 위험 신호에는 현황 없이 카드만 보인다
- 실패(연결 · 503)는 저장하지 않고 「다시 시도」만 준다 — 자동 재시도는 모델 호출을 한 번 더 내기 때문에 하지 않는다
- 한도(task common/005): 남은 정밀 답변이 3회 이하면 머리 오른쪽에 조용히 보이고, 다 쓴 뒤 보내면 `LimitBubble` 이
  「일반 기준으로 바로 답변」을 준다(같은 질문을 `mode: "eco"` 로). 광고 충전 단추는 보상형 광고가 붙으면 생긴다
- 피드백(task ask/003): 답 아래 좋아요·별로예요(`src/components/answer-feedback.tsx`). 별로예요는 선택 의견과
  「질문과 답도 함께 보내기」(기본 꺼짐)를 연다. 남긴 쪽은 말풍선 meta 에 저장돼 다시 열어도 보인다
