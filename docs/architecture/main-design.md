# 말콩(malkong) — 메인 설계

> status: draft | 작성: Julian & Claude | 2026-09-30

## 핵심 요약

**문제**: 육아 정보는 흩어져 있고(책·카페·검색), 내 아기의 상황에 맞춘 답은 없다. 기록 앱은 귀찮아서 끊긴다.

**해결**:
- 무엇이든 물어보면 **월령과 우리 아기 기록에 맞춰** 출처와 함께 답하는 앱을 만든다.
- 지식을 두 층으로 나눈다 — 공공 의료·육아 표준(L1)과 우리 아기 지식(L2). [지식층 설계](knowledge-layers.md)
- 기록을 따로 시키지 않는다. **대화가 곧 기록**이다 — 답하기 전에 필요한 것만 되묻고 그 답을 쌓는다.
- 표준(L1) 대비 기록(L2)의 차이가 곧 홈의 추천이 된다 — "놓친 것 · 다가오는 것".
- 묻기를 기다리지 않는다 — **매일 아침 비서가 먼저** 브리핑 카드(할 일·빠진 것·상태 확인)로 말을 건다.

**현재 상태**: 첫 출시판 기능 완성(대화 · 한도 · 피드백 · 광고 · 광고 제거 · 약관 초안). 2026-10-03 대화가 첫 화면인 탭 셋으로 다시 짰다.

## 사용자와 한 문장

생후 0~24개월 아기를 키우는 양육자. "**궁금할 때 물어보면, 우리 아기 기준으로 근거 있게 답해 주는 육아 동반자.**"

## 구조 — 하단 탭 4개

| 탭 | 역할 | 상세 |
|---|---|---|
| 말콩 | **첫 화면** — agent(말콩이)와의 대화. 하루 첫 메시지는 아침 브리핑, 지난 브리핑은 보관함에 | [ask](../menu-spec/ask.md) · 브리핑은 [home](../menu-spec/home.md) SPEC-HOME-06 |
| 우리 아기 | **말콩이가 아는 우리 아기** — 지식 지도(3D) · 아는 정도 · 한눈에 보는 프로필 · 알려 주면 좋아지는 것 · 함께 쌓아 온 흐름 · 기록 | [baby](../menu-spec/baby.md) |
| 성장 | **지금과 흐름** — 「이번 달」(챙길 것 · 발달 포인트) · 「타임라인」(0개월부터의 가로 타임라인) | [home](../menu-spec/home.md) · [growth](../menu-spec/growth.md) |
| 마이 | 프로필 · 알림 · 설정 · 광고 없이 쓰기 · 약관·고지 | [my](../menu-spec/my.md) |

대화가 첫 화면이다 — 앱을 열면 말콩이가 먼저 말을 건다([decisions/012](../decisions/012-chat-first-three-tabs.md)).
두 번째 탭은 product-brief 의 차별점 「우리 아기를 아는 AI」를 한 화면으로 보여 준다([decisions/013](../decisions/013-four-tabs-knowledge.md)).
「이번 달」은 현재 월령의 단면이고 「타임라인」은 전체 흐름이다.

| 구분 | 내용 |
|---|---|
| 1순위 | 온보딩(생일 1개) · 월령 실계산 · agent 답변(출처 포함) · **답변 피드백** · 대화 중 기록 수집 · 챙길 것 추천(차집합) · 타임라인 · **아침 브리핑(대화 첫 메시지 · 보관함 · 알림)** · 배너 광고 자리 |
| 다음 | **또래 질문 묶음(성장 탭, 캐시 답변)** · 로그인·**가족 공유(아기 프로필·기록 동기화)** · 전면 광고 · 타임라인 Skia 업그레이드 · 기록 수동 편집 · **대화 이력 검색·보관함**(SPEC-ASK-10) · **프로필·기록 사진**(SPEC-MY-02 — 기기 저장, 가족 공유 때 동기화) |
| 나중 | **또래 기록 분포**(동의를 받고 켜는 익명 통계 — "이 월령은 보통 밤중 수유 2회") · 검진 결과지 촬영 인식 · **사진으로 묻기**(SPEC-ASK-11) · **성취 카드·성장 리포트**(SPEC-GROW-06) · 다둥이 프로필 · 커뮤니티는 보기만 하는 익명 방식으로 — 락인 방향은 [product-brief](../product/product-brief.md) 「머무를 이유」 |
| 장기 비전 | L1 을 양방향 확장 — **1순위: 임신 준비~출산**(주수별 검사·영양제·준비물·조리원·혜택), 2순위: 취학 준비 → 교육과정·입학 전략 → 성인 이행기. [product-brief](../product/product-brief.md) 장기 비전 절이 정본 |
| 하지 않음 | 진단·처방에 해당하는 답변 · 전량 수동 육아 기록 · 상업 서적 내용의 재제공 · 부모끼리 순위·비교 · 사용자끼리 의료 답변을 주고받는 게시판 · 사진 모으기 자체가 목적인 앨범·일기 — 뒤의 셋은 이유가 product-brief 「머무를 이유」에 있다 |

## 수익 모델

구독·과금 전까지 광고로 간다 — 배너(성장 탭)와 전면(기록 저장 같은 완결 시점).
**광고 제거는 한 번 결제로 산다**(SPEC-MY-06) — 광고만 사라지고 질문 한도·답변 품질은 그대로다.
자리는 [app-design](../app-design/README.md)의 광고 절.

## 서버 · DB · LLM

[backend](backend.md)에 있다 — FastAPI 경량 서버(Cloud Run, scale-to-zero) · 아기 데이터는 기기
sqlite 에 두고 운영 데이터(사용량·집계·피드백·캐시)만 Neon(서버리스 Postgres)에 · LLM 질문 라우팅
(규칙 → 캐시 → 고정한 모델 하나) + 일일 한도.
기기 DB 스키마도 같은 문서에 있다. 앱과 서버 사이 API 는 [api-contract](api-contract.md),
L1 지식의 실체(항목 스키마·출처 화이트리스트·구축 절차)는 [l1-knowledge-base](l1-knowledge-base.md)가 정본이다.
