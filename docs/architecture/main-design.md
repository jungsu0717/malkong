# 말콩(malkong) — 메인 설계

> status: draft | 작성: Julian & Claude | 2026-09-30

## 핵심 요약

**문제**: 육아 정보는 흩어져 있고(책·카페·검색), 내 아기의 상황에 맞춘 답은 없다. 기록 앱은 귀찮아서 끊긴다.

**해결**:
- 무엇이든 물어보면 **월령과 우리 아기 기록에 맞춰** 출처와 함께 답하는 앱을 만든다.
- 지식을 두 층으로 나눈다 — 공공 의료·육아 표준(L1)과 우리 아기 지식(L2). [지식층 설계](knowledge-layers.md)
- 기록을 따로 시키지 않는다. **대화가 곧 기록**이다 — 답하기 전에 필요한 것만 되묻고 그 답을 쌓는다.
- 표준(L1) 대비 기록(L2)의 차이가 곧 홈의 추천이 된다 — "놓친 것 · 다가오는 것".
- 묻기를 기다리지 않는다 — **매일 아침 비서가 먼저** 브리핑 카드(할 일·빠진 것·상태 확인)로 말을 건다.

**현재 상태**: 4탭 화면 뼈대와 지식층 데이터 모형까지. agent 백엔드·온보딩·광고 SDK 는 미착수.

## 사용자와 한 문장

생후 0~24개월 아기를 키우는 양육자. "**궁금할 때 물어보면, 우리 아기 기준으로 근거 있게 답해 주는 육아 동반자.**"

## 구조 — 하단 탭 4개

| 탭 | 역할 | 상세 |
|---|---|---|
| 홈 | **지금** — 아기 상태 요약과 챙길 것 추천 | [menu-spec/home.md](../menu-spec/home.md) |
| 물어보기 | agent(말콩이)와의 대화. 답변과 기록 수집이 한 곳에서 | [menu-spec/ask.md](../menu-spec/ask.md) |
| 성장 | **시간축 전체** — 0개월부터의 가로 타임라인, L1·L2 교차 | [menu-spec/growth.md](../menu-spec/growth.md) |
| 마이 | 온보딩·프로필·약관·고지 | [menu-spec/my.md](../menu-spec/my.md) |

홈은 현재 월령의 단면이고 성장은 전체 흐름이다 — 이 구분으로 두 화면이 겹치지 않는다.

**탭 밖의 전역 요소** (비서는 어느 화면에나 있다):

- **플로팅 질문 버튼** — 물어보기 탭 밖 모든 탭의 우하단. 누르면 그 자리에서 입력창이 열리고,
  전송하면 물어보기 탭으로 이동해 대화가 이어진다. SPEC 은 [ask](../menu-spec/ask.md) SPEC-ASK-07.
- **아침 브리핑 카드** — 매일 아침 푸시로 오고 홈의 인박스에 쌓인다. SPEC 은 [home](../menu-spec/home.md) SPEC-HOME-06.

## 범위

| 구분 | 내용 |
|---|---|
| 1순위 | 온보딩(생일 1개) · 월령 실계산 · agent 답변(출처 포함) · **답변 피드백** · 대화 중 기록 수집 · 홈 추천(차집합) · 타임라인 · **플로팅 질문 버튼** · 배너 광고 자리 |
| 다음 | **아침 브리핑 카드(푸시+인박스)** · **또래 질문 묶음(성장 탭, 캐시 답변)** · 로그인·**가족 공유(아기 프로필·기록 동기화)** · 전면 광고 · 타임라인 Skia 업그레이드 · 기록 수동 편집 |
| 나중 | 검진 결과지 촬영 인식 · 다둥이 프로필 · 커뮤니티성 기능 검토 |
| 장기 비전 | L1 을 양방향 확장 — **1순위: 임신 준비~출산**(주수별 검사·영양제·준비물·조리원·혜택), 2순위: 취학 준비 → 교육과정·입학 전략 → 성인 이행기. [product-brief](../product/product-brief.md) 장기 비전 절이 정본 |
| 하지 않음 | 진단·처방에 해당하는 답변 · 전량 수동 육아 기록 · 상업 서적 내용의 재제공 |

## 수익 모델

구독·과금 전까지 광고로 간다 — 배너(홈·성장 하단)와 전면(기록 저장 같은 완결 시점).
구현 기준은 [app-design](../app-design/README.md)의 광고 절.

## 서버 · DB · LLM

[backend](backend.md)에 있다 — FastAPI 경량 서버(클라우드 scale-to-zero) · DB 2단계(기기 sqlite,
가족 공유부터 관리형 Postgres) · LLM 질문 라우팅(규칙 → 캐시 → 소형 모델 → 승급) + 일일 한도.
기기 DB 스키마도 같은 문서에 있다. 앱과 서버 사이 API 는 [api-contract](api-contract.md),
L1 지식의 실체(항목 스키마·출처 화이트리스트·구축 절차)는 [l1-knowledge-base](l1-knowledge-base.md)가 정본이다.
