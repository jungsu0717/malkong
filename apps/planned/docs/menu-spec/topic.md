# 주제 탭 — 주제 만들기, 추천 할 일, 기본 가이드, 보관함

> 위에 있는 것: [constitution](../constitution.md) 3 · 4 · 8 · [main-design](../architecture/main-design.md)

## SPEC

### SPEC-TOPIC-01 주제 만들기
```
평시 ▸ 주제는 종류(오늘, 퇴근 전, 장보기, 여행, 회사, 운동, 행사, 직접 입력)와 이름으로 만들 수 있어야 한다.
       기간, 시간대, 반복, 장소는 고를 수 있지만 필수가 아니다.
평시 ▸ 처음 설치하면 「오늘」 주제가 하나 있어야 한다.
```

### SPEC-TOPIC-02 추천 할 일
```
평시 ▸ 새 주제를 만들면 같은 종류의 지난 주제들에서 두 번 이상 나온 할 일을 추천 목록으로 보여 줘야 한다.
       사용자는 하나씩 또는 한꺼번에 넣을 수 있다.
평시 ▸ 같은 종류의 지난 주제가 없으면 그 종류의 기본 가이드 목록을 추천으로 보여 줘야 한다.
평시 ▸ 「AI 로 시작 목록 만들기」를 누르면 주제 이름과 기간으로 시작 목록을 만들어 추천으로 보여 줘야 한다. 하루 한도는 붙여 넣기와 같이 센다.
```

### SPEC-TOPIC-03 기본 가이드
```
평시 ▸ 장보기와 오늘 할 일에는 처음 쓰는 사람이 따라 하기 쉬운 짧은 안내와 시작 목록이 있어야 한다.
평시 ▸ 그 종류의 주제를 처음 만들 때 안내를 한 번 보여 주고, 다시 보기는 주제 화면에서 열 수 있어야 한다.
```
미결: 장보기, 오늘 할 일 말고 어떤 가이드를 첫 판에 둘지(product-brief 「열린 질문」).

### SPEC-TOPIC-04 보관함
```
평시 ▸ 기간이 끝났거나 할 일을 다 끝낸 주제는 「보관할까요?」를 묻고, 보관하면 보관함으로 옮겨야 한다.
평시 ▸ 보관한 주제에서 「다시 쓰기」를 누르면 같은 할 일로 새 주제를 만들 수 있어야 한다(끝낸 표시는 지운 채로).
금지 ▸ 보관한 주제와 그 할 일을 사용자가 지우지 않았는데 지워서는 안 된다.
```

### SPEC-TOPIC-05 완성도
```
평시 ▸ 주제 목록과 주제 화면에 끝낸 수와 전체 수가 보여야 한다.
```

## HOW

- 추천 계산: 같은 종류의 보관 · 진행 주제에서 제목(띄어쓰기 뺀 글자)별로 센다. 저장하지 않는다
- 기본 가이드: 앱 안의 JSON 파일(종류별 안내 문장과 시작 목록). 서버에서 내려받지 않는다
- AI 시작 목록: `POST /v1/starter`
