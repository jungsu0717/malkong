# 002 서버가 원본, 폰은 복사본, Apple 로그인 먼저

> 상태: 확정 (2026-10-14)

## 맥락

육아버디는 아기 건강 기록이라 폰 안에만 저장한다. Planned 는 쌓인 기록이 곧 가치라서, 기록이 날아가면 사용자가 떠난다.
Julian(2026-10-14): 「폰 안에 sqlite 로 가두는 게 맞나 싶다. 쌓인 데이터가 날아가기라도 하면 안 쓸 것 같다.」
장보기 목록이나 여행 준비물은 건강 기록보다 민감도가 낮다. 그리고 링크로 함께 쓰기는 주제가 서버에 있어야 된다.

## 결정

- 서버(Neon, 육아버디와 다른 프로젝트)가 원본이고 폰은 복사본이다. 인터넷이 없어도 적을 수 있고, 연결되면 맞춘다.
  맞추는 방식은 육아버디 가족 맞추기의 「순번, 나중에 쓴 쪽이 이김」을 쓴다
- 로그인은 **Apple 로그인**을 먼저 둔다. 처음 실행에서 권하되 건너뛸 수 있고, 건너뛰면 기기 키로 서버에 저장한다.
  나중에 로그인하면 그 기록을 계정에 묶는다. 로그인하지 않은 동안에는 「앱을 지우면 기록이 사라져요」를 마이 탭에 보여 준다
- 탈퇴하면 서버의 모든 기록(붙여 넣은 원문 포함)을 지운다
- 개인정보 처리방침에 서버 저장, 암호화, 삭제를 실제대로 적는다

## 기각한 대안과 이유

- **폰에만 저장** — 폰을 바꾸거나 앱을 지우면 기록이 사라진다. 이 앱의 두 번째 가치(쌓인 기록)가 없어진다
- **기기 키만으로 서버 저장** — 앱을 지웠다 깔면 새 키가 생겨서 서버의 기록을 찾지 못한다
- **카카오 로그인 먼저** — 네이티브 모듈이라 개발 빌드가 있어야 하고, 소셜 로그인을 하나라도 쓰면 애플 규정상 Apple 로그인이 어차피 필요하다. 카카오는 나중에 더한다
