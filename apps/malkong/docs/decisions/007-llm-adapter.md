# 007 모델 연결은 각 회사 공식 SDK 를 우리 어댑터 뒤에 둔다

> 상태: 확정 (2026-10-02)

## 맥락

backend 는 처음에 "대부분의 모델사가 OpenAI 호환 API 를 주므로 호환 인터페이스 하나(필요하면 LiteLLM)로
붙인다"고 정했다. 모델 비교(task common/003)에서 Gemini 와 Claude 를 실제로 붙이려고 두 회사의 현재 문서를
확인해 보니, 그 전제가 우리에게 필요한 기능에서 맞지 않았다.

- Claude 의 OpenAI 호환 계층은 공식 문서에 "모델 능력을 시험하고 비교하는 용도이며, 대부분의 경우
  장기적이거나 운영에 쓸 수 있는 방식이 아니다"라고 적혀 있다. 그리고 `response_format`(JSON 형식 강제)과
  프롬프트 캐싱을 **조용히 무시한다**
- 우리 답변은 정해진 JSON(수위, 답, 인용 id, 되묻기, 기록 후보)으로 와야 하고, 공통 시스템 프롬프트는
  캐싱해야 한다(backend LLM 파이프라인). 둘 다 호환 계층에서 빠지는 기능이다
- Gemini 는 새 Interactions API 를 내놓았고, 대화를 서버에 남기지 않는 `store=False` 같은 설정이 그쪽에 있다

## 결정

각 회사의 **공식 SDK**(`anthropic`, `google-genai`)로 붙이고, 그 차이는 우리 어댑터 계약
(`server/app/infra/llm/base.py` — 요청: 시스템, 사용자 메시지, JSON 스키마 / 결과: JSON, 토큰, 지연, 실제로 답한 모델)
뒤에 숨긴다. 프롬프트, 채점, `/v1/ask` 는 이 계약만 본다. 모델을 바꾸는 것은 여전히 설정값 교체이고 앱 업데이트가
필요 없다. 정의는 [backend](../architecture/backend.md) 「모델은 갈아끼우는 부품이다」.

Claude 는 **Vertex AI**(같은 GCP 프로젝트 `malkong`)로 부르는 것을 기본으로 한다. 같은 anthropic SDK 의
`AnthropicVertex` 로 붙고, Claude API 직결은 설정으로 고를 수 있는 다른 길로 남긴다.

## 기각한 대안과 이유

- **OpenAI 호환 API 하나로** — 위 맥락대로 Claude 쪽에서 JSON 형식 강제와 캐싱이 빠진다. JSON 이 깨지면
  출처 검사(SPEC-ASK-01)부터 흔들린다
- **LiteLLM 같은 통합 라이브러리** — 회사별 새 기능(Gemini Interactions API, Claude 의 거절 시 자동 대체)이
  라이브러리에 들어올 때까지 기다려야 하고, 문제가 생기면 한 겹 더 들여다봐야 한다. 우리가 쓰는 모델은
  한 번에 하나라서 어댑터 두 개(각 수십 줄)면 충분하다
- **한 회사 SDK 만 쓰기** — 비교 자체를 할 수 없고, "모델은 갈아끼우는 부품"이라는 원칙과 어긋난다
- **Claude 를 Anthropic 콘솔(직결)로만 부르기** — 개인 콘솔 계정과 선불 크레딧을 따로 만들어야 하고,
  키를 하나 더 보관해야 한다. Vertex 로 부르면 결제와 예산 알림이 이미 있는 GCP 로 묶이고, 키 대신
  계정 권한(로컬은 gcloud 로그인, Cloud Run 은 서비스 계정)을 쓴다. 우리에게 필요한 JSON 형식 강제와
  프롬프트 캐싱은 Vertex 에서도 되고, 글로벌 엔드포인트 가격도 직결과 같다(2026-10-02 가격표).
  빠지는 것은 거절 시 서버 쪽 자동 대체 하나다
