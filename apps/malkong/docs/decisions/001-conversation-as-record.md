# 001 기록은 대화의 부산물로 쌓는다

> 상태: 확정 (2026-09-30)

## 맥락

agent 가 정확히 답하려면 아기 정보(수유 텀·몸무게·접종 이력 등)가 필요하다.
이 정보를 어떻게 모을 것인가.

## 결정

답변 전 되묻기(1~2개, 칩 제공)로 모으고 기록으로 저장한다. 재질문 금지·저장 표시·이벤트 시점
리마인드가 한 벌이다. 정의는 [knowledge-layers](../architecture/knowledge-layers.md) 「채워지는 경로」와
SPEC-ASK-03 에 있다.

## 기각한 대안과 이유

- **전량 수동 기록 (기록 앱 방식)** — 기록이 별도의 일이 되는 순간 이탈한다. 기존 기록 앱들과의
  경쟁이 되고, 우리 강점(답변)이 아니라 약점(기록 UI)으로 싸우게 된다.
- **온보딩에서 설문으로 한꺼번에 수집** — 시작 장벽이 커지고, 쓰이지 않을 정보까지 요구하게 된다.
  온보딩 필수 입력은 생일 하나로 못 박았다(SPEC-MY-01).
- **묻지 않고 일반론으로만 답하기** — 개인화가 사라져 범용 챗봇과 차이가 없어진다.
