# 021 가족 공유는 초대 코드와 기기 키로 — 로그인은 뒤에

> 상태: 확정 (2026-10-12)

## 맥락

가족 공유(SPEC-MY-05)를 빨리 쓰고 싶다(Julian, 2026-10-12 「그냥 만들어서 넣자」). 2026-10-06 에는 「로그인은 가족 공유를 만들 때,
Apple + 카카오」로 정해 두었는데, 그 길은 애플 개발자 등록 · 카카오 개발자 앱 등록 · 개발 빌드가 먼저 있어야 하고 카카오 로그인은
Expo Go 에서 돌지 않아 몇 주가 걸린다.

## 결정

가족은 **초대 코드 6자리와 기기 키**로 묶는다. 로그인 없이, 지금 있는 기기 키 해시가 구성원의 정체다. 정의는
[my](../menu-spec/my.md) SPEC-MY-05 · [api-contract](../architecture/api-contract.md) `/v1/family` · [backend](../architecture/backend.md)
「DB — 두 단계」. 로그인(SPEC-MY-04)은 **기기 이전**(폰을 바꿔도 가족과 기록을 되찾기)이 필요해질 때 붙이고, 그때 가족을 계정에 묶는다.

맞추기는 「늦게 고친 쪽이 이긴다」(updatedAt) + 서버 번호(seq)로 「그 뒤에 바뀐 것만」. 아기 기록은 건강 정보라 민감정보 —
켤 때 따로 동의를 받고 동의한 때를 남긴다.

## 기각한 대안과 이유

- 로그인(Apple + 카카오)부터 — Julian 쪽 준비(계정 · 빌드)가 끝나야 시작할 수 있어 몇 주가 걸리고 Expo Go 로 못 본다. 가족 공유 자체에는
  계정이 필요 없다. 다만 폰을 잃으면 가족 코드를 다시 받아야 하는 약점은 로그인을 붙일 때 사라진다
- 서버 없이 폰끼리 직접(근거리 · 링크) — 서로 켜져 있을 때만 맞고, 셋 이상이면 꼬인다. 서버가 가운데 있어야 「언제 적어도 다음에 받는다」
- 변경 로그(CRDT · 작업 기록)로 합치기 — 기록은 한 줄짜리라 같은 줄을 동시에 고칠 일이 드물다. LWW 가 충분하고 단순하다
- 증분 대신 전부 받기 — 기록은 수백 줄까지 자랄 수 있어 번호로 「그 뒤 것만」 받는다(지식 묶음과 달리)
