# 003 백엔드는 FastAPI 경량 서버 + 클라우드 관리형으로

> 상태: 확정 (2026-09-30)

## 맥락

LLM API 키를 앱에 심을 수 없어 서버가 필수인데, 운영할 물리 서버(집 PC 등)가 없고
초기엔 유저가 적어 고정비를 만들면 안 된다.

## 결정

FastAPI 단일 경량 서버(LLM 프록시·L1 검색·사용량 제어)를 scale-to-zero 클라우드 호스팅에 두고,
서버 DB(관리형 Postgres)는 가족 공유 도입 시점에 추가한다. 정의는 [backend](../architecture/backend.md).

## 기각한 대안과 이유

- **자가 서버(집 PC·NAS)** — 없다. 있어도 가용성·보안 운영이 개인 프로젝트 범위를 넘는다.
- **Supabase 단독(BaaS)** — DB·인증은 좋지만 LLM 프록시·라우팅 로직을 Edge Function(TypeScript)으로
  짜야 해서 FastAPI 역량을 못 쓴다. Postgres 가 필요해지는 시점에 DB 로만 부분 채택 후보.
- **처음부터 서버 DB 중심** — 로그인 의무화가 당겨지고 constitution 원칙 4(아기 데이터는 초기 기기 안)와
  충돌한다. 챗 이력까지 서버에 두는 것은 가족 공유 후에도 하지 않는다.
