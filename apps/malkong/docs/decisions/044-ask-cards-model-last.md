# 044 질문은 규칙과 카드로, 모델은 고치는 말과 다 못 읽은 기록에만 — 끌 수 있는 보조

> [040](040-ask-agent-reads-the-day.md) · [043](043-agent-knows-app-tools.md)의 한 번 호출과 기능 목록은 그대로 두고, 무엇을 모델로 보낼지를 좁힌다.

## 맥락

- Julian(2026-11-10): 「유저 prompt 는 예측을 할 수 없잖아. 그때 우리 agents builder 에 붙은 selvas 처럼 뭘 물어본건지 한단계 카드형태로 묻는 형태로 하면 정확한 답변을 유도할 수 있지않아?」
- 비용을 셈해 보니(기능 목록을 넣은 뒤 한 번 2.6원, 보통으로 쓰는 사람 한 달 200원쯤) Julian 이 「그냥 외부 모델을 없애는게 나으려나」. 같은 날 Gemini 가 몇 시간 503(붐빔)이었다.
- 웹 시험에서는 질문 대부분을 규칙이 이미 답했고, 모델이 질문을 받으면 정해진 기록 종류에 억지로 맞춰 엉뚱하게 답한 일이 있었다(빌드 15 「손톱 잘랐나?」).

## 결정

- **질문은 모델로 보내지 않는다.** 규칙(찾기, 이름 찾기, 깬 시각, 누가, 앞 기록 비교, 하루 요약)과 앱 기능(두 기간 견주기, 수유 간격)으로 답한다.
  기간 없는 견주기(「낮잠 줄었어?」)처럼 뜻이 여럿이면 「어떤 걸 알려 드릴까요?」 카드에 기능 셋을 보이고, 고르면 앱이 실행한다.
  그래도 못 읽은 질문에는 문장에 나온 기록 종류에 맞춰 할 수 있는 것 셋을 같은 카드로 보인다. 카드의 글은 앱이 기능 목록에서 쓴다(헌장 13).
- **모델은 가리키는 말(「이거」), 고치는 말(「옮겨 줘」, 「지워 줘」), 규칙으로 다 읽지 못한 기록하는 말에만 쓴다.** 여러 기록이 섞인 말도 조각을 모두 규칙으로 읽으면 보내지 않는다.
- **서버에 끄는 스위치를 둔다**(`MALKONG_AGENT_ENABLED`). 끄면 503 이고 앱은 규칙과 카드로만 답한다 — 앱을 새로 내지 않고 비용을 0 으로 만들거나 붐빌 때 끈다.
- **모델로 간 횟수만 센다.** 부를 때마다 답의 종류, 고른 기능 이름, 보낸 기록 수만 로그에 적는다(문장과 기록 내용은 적지 않는다). TestFlight 동안 이 숫자를 AdMob 수익과 견줘 출시 때 끌지 정한다.

## 기각한 대안과 이유

- **모델을 지금 없애기** — 말로 고치기와 섞인 기록 읽기를 잃는다. 지금 비용은 가족 몇 명이라 한 달 몇백 원이고, 끌지 판단할 숫자(모델로 가는 비율, 한 사람당 광고 수익)가 아직 없다. 스위치로 언제든 끈다.
- **모델이 후보를 골라 카드로 보이기(type choose)** — 시안 설명에서는 모델이 뜻이 여럿일 때 후보를 돌려주게 했지만, 질문을 모델로 보내지 않기로 해서 앱 규칙이 후보를 고른다. 모델 호출이 줄고 답이 빨라진다.
- **카드를 늘 보이기** — 분명한 질문까지 한 번 더 누르게 하면 귀찮다. 뜻이 여럿이거나 못 읽었을 때만.
