> 근거: SPEC-ASK-01(출처) · SPEC-ASK-02(위험 신호 고정 응답) · SPEC-ASK-03(되묻기) · SPEC-ASK-08(답변 수위) —

## 목표

`POST /v1/ask` 를 목업에서 실제 답변으로 바꾼다. 위험 신호는 모델을 부르지 않고 규칙이 먼저 막고,
나머지는 승인된 L1 에서 골라낸 조각과 함께 고정 모델(Gemini 3.5 Flash-Lite, decisions/008)이 답하며,
서버가 그 답을 검사한 뒤 내보낸다. 로컬과 Cloud Run 에서 끝까지 동작하는 것이 이 task 의 끝이다.

- **캐시(라우팅 ②)** — 캐시할 답이 쌓인 뒤에. 또래 질문 묶음과 함께

## 먼저 정한 것

1. **근거 없는 질문의 답 (Julian 결정, 2026-10-02)** — 헌법 1조와 계약은 "출처 없는 답 금지", SPEC-ASK-08 은
   "일반 정보는 '일반적으로는'을 밝혀 답한다"로 서로 부딪혔다. **일반 정보로 답하고 그렇다고 표시한다**로 정했다.
   헌법 1조를 "근거 없는 답을 근거 있는 척 내보내지 않는다"로 다듬고, 계약에 `level` 을 더해 sources 가
   빌 수 있는 경우를 "인용 없는 일반·판단 답" 하나로 좁힌다(사실 답은 반드시 출처가 있다)
2. **무료 티어에는 아기 기록을 보내지 않는다** — 지금 키는 결제가 없는 무료 티어다(입력이 학습에 쓰일 수 있다).
   설정 `llm_paid_tier` 가 꺼져 있으면 서버는 L2 기록을 모델에 넣지 않고 응답에 `eco: true` 를 단다.
   유료 전환은 실사용 전에 Julian 이 한다(task common/003 「이 task 다음」)
3. **서버가 L1 을 읽는 법** — 서버는 자기 폴더 안의 사본(`server/app/data/l1/`)을 읽는다. 사본은
   `uv run python -m scripts.sync_l1` 로 만들고, 원본(`src/data/l1/`)과 다르면 테스트가 실패한다.
   그래서 배포 명령(`--source .`)과 Dockerfile 은 그대로다. 빌드 범위를 repo 루트로 넓히는 안은
   검증할 gcloud 가 이 맥에 없어 기각했다

## 단계

1. 문서 — 헌법 1조 · api-contract(`level`, 일반 정보일 때만 빈 sources, 모델 오류 코드) · ask HOW
2. L1 사본과 로더 — `scripts/sync_l1.py`, `app/data/l1/`, 승인된 항목만 읽기
3. 위험 신호 규칙 필터 — `app/domain/ask/redflag.py`. 범주마다 문장 규칙과 L1 항목(k-warn-*),
   맞으면 모델 없이 고정 응답. **규칙은 초안 → 검증 에이전트 → Julian 승인**(의료 게이트, L1 과 같은 절차)
4. L1 검색 — `app/domain/ask/retrieval.py`. 질문에 나온 월령(없으면 아기 월령)과 분류 낱말로 고른다.
   모델 비교 질문 세트(`eval/questions.json`)의 정답 id 를 다시 찾아내는지로 시험한다
5. 모델 호출과 검사 — `service.py`. 인용 id 가 준 조각 안에 있는지, 사실 수위에 인용이 있는지,
   판단 수위에 안심 표현이 없는지(있으면 한 번 다시 생성, 그래도 있으면 진료 권유 고정 문장).
   모델이 답하지 못하면 503 `MODEL_UNAVAILABLE`
6. 실제 모델로 끝까지 — 로컬 서버에 지어낸 질문(사실·일반·판단·되묻기·위험 신호)을 보내 본다

## 검증 (2026-10-02)

- **L1 검색** — 모델 비교 질문 세트의 사실 질문 10개가 정답 L1 을 모두 다시 찾는다. 근거 없는 주제(손톱·몸무게·
  납작 머리)에는 아무것도 붙이지 않는다. 처음에는 "아기", "어요" 같은 흔한 글자 조합으로 엉뚱한 항목(몸무게
  질문에 카시트 항목)이 붙어서, L1 전체에서 드문 조합만 세도록 고쳤다
- **위험 신호 규칙** — 검증 에이전트가 부모 말투로 만든 문장으로 두 번 검증했다. 1차에서 23건(가장 위험한 것:
  "경련이 멈추지 않아요"를 증상 없음으로 읽음, "열났어요"·"소변을 보지 않았어요" 놓침, "분유 물 40도" 오탐)을
  찾아 규칙을 다시 짰다 — 부정은 그 구절 안에서만, "멈추지 않아요"는 증상이 계속되는 것으로, 숫자는 단위와
  문맥으로 체온을 가린다. 시험 표 163문장 통과
- **코드 리뷰** — 12건 반영. 가장 중요한 둘: 무료 티어에서 되묻기가 끝없이 반복되던 것(기록을 못 보내니 칩으로
  답해도 같은 질문), 모델 설정이 틀리면 위험 신호 응답까지 500 이 되던 것. 그 밖에 시간 초과(20초), 우리 코드의
  버그는 503 으로 덮지 않기, 오류 메시지에 모델 출력을 넣지 않기, 빈 답·잘못된 되묻기 다시 생성, 빈 L1 은 시작할 때 실패
- **실제 Gemini**(무료 티어, 지어낸 질문) — 사실(6개월 접종 7건, 출처 7개) · 일반(손톱, 출처 없음·"일반적으로") ·
  판단 6개(안심 표현 0건, 진료 권유) · 무료 티어 되묻기 대신 일반 답 · 위험 신호(1개월 38.2도 → 0.0초 고정 응답) ·
  새 CDC 주제(꿀 → 12개월 전 금지) 모두 기대대로
- 서버 테스트 259개
- **위험 신호 2차 검증 — 규칙만으로는 모자랐다.** 처음 보는 부모 말투 181문장 중 92문장(51%)만 잡았고,
  일상 질문 110개 중 10개를 잘못 잡았다("머리둘레 40.5", "고개가 축 처져요"). 줄임꼴("멈추질 않아요"),
  "동안"의 "안", 활용형("힘든·파랬"), "방금"의 "방" 같은 구멍이 바퀴마다 새로 나와 **Julian 결정으로
  두 겹 판별로 바꾼다**(decisions/010). 검증 에이전트의 문장 표는 두 겹 판별을 시험할 때 다시 쓴다
- **배포 확인**(Cloud Run, Gemini 1회) — `/health` ok · "아기가 경련을 해요" → 모델 없이 0.35초 고정 응답(k-warn-0004) ·
  "2개월 접종 뭐 맞아요?" → 사실 수위, 질병관리청 출처 5개, 3.3초, `eco: true`
