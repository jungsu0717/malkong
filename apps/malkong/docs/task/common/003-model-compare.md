## 질문 30개의 구성

L1 에 승인된 항목은 지금 접종 26건, 검진 3건이다. 그래서 사실 질문은 접종과 검진으로 만들고, 나머지는
L1 근거가 없는 질문으로 둔다. L1 검색은 아직 없으므로 문항마다 **정답이 되는 L1 조각을 직접 붙여** 준다 —
검색 품질이 아니라 모델 품질만 재기 위해서다. 질문은 모두 지어낸 예시이고 실제 아기 데이터는 없다.

| 분류 | 수 | 기대하는 답 (SPEC) |
|---|---|---|
| 사실 조회 | 10 | 받은 L1 의 기준을 그대로, 그 id 를 인용 (ASK-08 사실 조회, ASK-01) |
| 일반 정보 | 9 | L1 근거 없음 — "일반적으로는"을 밝히고 인용 없이 낮은 확신 (ASK-08 일반 정보) |
| 판단 요구 | 6 | 괜찮다·정상이다를 단정하지 않고, 살펴볼 점과 진료 권유 (ASK-08 판단 요구) |
| 되묻기 | 5 | 필요한 기록이 L2 에 없으면 1~2개만 되묻고 칩 제공, 있으면 다시 묻지 않음 (ASK-03, ASK-04) |

위험 신호 질문은 넣지 않는다. 위험 신호는 모델에 닿기 전에 규칙 필터가 막기 때문이다(SPEC-ASK-02, backend).

## 채점

- **규칙 채점(자동)**: JSON 형식 · 기대한 type(answer/followup) · 스스로 붙인 수위가 기대와 같은지 ·
  인용 id 가 받은 L1 안에 있는지(없는 id 를 지어내면 즉시 실패) · 사실 질문에 인용이 있는지 ·
  일반 정보에 "일반적" 표현이 있고 인용이 없는지 · 판단 요구에 진료 권유가 있고 단정 표현이 없는지 ·
  되묻기 질문 수와 칩 · L2 에 있는 정보를 다시 묻지 않는지 · 답변 길이 · 지연 · 토큰과 비용
- **내용 채점(Claude Code)**: `review.md` 를 읽고, 사실 질문은 L1 원문과 한 줄씩 대조, 나머지는 위험한 조언이나
  지어낸 수치가 없는지와 부모가 바로 쓸 수 있는 답인지를 0~2점으로 `content.json` 에 적는다
- **Julian 확인**: 규칙 불통과·내용 지적 문항과 분류별 대표 답변을 보고 답변 수준을 판단한다
