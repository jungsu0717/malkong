# 001 L1 지식베이스 1차 구축 — 라이선스 확인부터

> 상태: 진행 — 1단계 1곳(중앙육아종합지원센터) 남음 · 2~4단계 완료 · 5단계 접종·검진·발달 반영 · 6단계 남음 (2026-10-02)
> 근거: SPEC-ASK-01(출처 화이트리스트) · SPEC-ASK-02(위험 신호 기준) · SPEC-HOME-02(추천의 재료) ·
> SPEC-HOME-03(발달 포인트) · SPEC-GROW-02(표준 트랙) — 정본: [l1-knowledge-base](../../architecture/l1-knowledge-base.md)
> 횡단(common): 물어보기 답변·홈 추천·성장 타임라인이 모두 이 데이터를 소비한다

## 목표

0~12개월 × 7분류(접종·검진·발달·수유·수면·생활·안전)와 위험 신호(대응) 150~250항목의 L1 지식을
항목 스키마대로 구축한다. 1단계가 걸려 있는 미결(출처 라이선스)의 해소다.

## 단계

1. **출처 7곳 라이선스 확인** — **6곳 완료(2026-10-01), 중앙육아종합지원센터 1곳 남음**. 결과는 l1-knowledge-base 화이트리스트 표,
   결정은 [decisions/005](../../decisions/005-source-license-scope.md).
   본문 근거는 **질병관리청 본청·CDC 둘**로 좁혔고, 국가건강정보포털(공공누리 제4유형)·WHO(CC BY-NC-SA)·
   소아청소년과학회는 사실 확인과 링크에만 쓴다. 예방접종도우미·국민건강보험공단은 3단계에서 쓰는
   자료의 배지를 확인했고(둘 다 배지 없음 — 사실 확인과 링크), 중앙육아종합지원센터는 해당 항목을 쓸 때 확인한다
2. ~~저장 형식 확정 — `src/data/l1/` 항목 파일 + 로더 + 판 번호~~ — **완료(2026-10-01)**.
   분류별 JSON + `index.ts` 로더. 스키마에 **`status`(draft·approved)** 를 더해 **승인 전 항목이
   화면·답변에 나가지 않게** 했다 — 의료 게이트를 절차가 아니라 코드가 지킨다. 개발 중에는 출처
   누락·id 중복을 찾아 경고한다. 쌓인 정도는 마이 탭 「구축 현황」에 보인다(구축 중에만 두는 칸)
3. 접종·검진부터 증류 — 홈 차집합 추천이 먼저 쓰는 분류. AI 초안 → **Julian 검토·승인(의료 게이트)**.
   **완료 — 초안·검증·Julian 승인(2026-10-01).** 0~12개월에 시작하는 접종 26건(질병관리청 표준예방접종일정표
   2026)·검진 3건(국민건강보험공단 영유아 건강검진 1~3차), 모두 `approved`. 두 출처 모두 배지가 없어
   일정·항목 사실만 우리 문장으로 쓰고 링크를 단다. 접종은 백신·차수마다 한 항목이다(기록이 하나씩
   완료 처리할 수 있게). 신생아 선별검사(선천성 대사이상·청각)는 화이트리스트 출처가 없어 넣지 않았다.
   별도 에이전트가 원본과 대조 검증(2026-10-01) — 사실 오류 0건, 누락·표현 7건을 고쳤다.
   A형간염 2차·일본뇌염 2차부터는 일정표에 차수별 시기가 없어 13~24개월 구축 때 다른 KDCA 출처로 쓴다.
   백신 종류에 따라 갈리는 일정(로타 RV1·RV5)은 5단계에서 풀었다
4. 발달·수유·수면·안전 증류 — 같은 절차. red_flag 항목은 기준 수치가 출처와 일치하는지 검수 2회.
   **완료 — 초안·검증 2회·Julian 승인(2026-10-02).** 발달 6(CDC 이정표 2·4·6·9·12개월 + 조기 상담) · 수유 14 ·
   수면 6 · 생활 3 · 안전 7 · 대응(위험 신호, red_flag) 8 = 44건, 모두 CDC(퍼블릭 도메인)라 본문 재서술.
   위험 신호 수치: 3개월 미만 38°C(UTI 안내) · 40°C 해열제 무효·12주 미만 모든 열·호흡곤란·청색증·경련·
   의식 저하·탈수 8시간(독감 응급 경고 신호) · 머리 부딪힘 위험 징후(HEADS UP) · 구토·설사 2일·혈변·
   102°F(대장균 안내). 질병관리청 국가건강정보포털은 검색에서 원문 페이지를 못 찾아 쓰지 않았다 —
   국내 기준으로 보강할 때 다시 본다. 발달 이정표는 월령당 한 항목(제목 = 한 줄 요약, 본문 = 영역별 전체)으로
   두어 홈 「발달 포인트」는 제목만 보여도 된다.
   **검증(2026-10-02)**: 에이전트 둘이 따로 — 하나는 44건 전체를 19개 출처 페이지와 대조, 다른 하나는 red_flag
   8건의 수치만 다시(검수 2회 규칙). 사실·수치 오류 0건. 고친 것 15군데 — 출처에 없는 문장 4(비타민 D 역추론·
   "열 자체가 응급"·"매일"·"아기마다 차이"), 출처보다 강한 표현 2("막는다"→"위험을 줄인다", "응급 진료"→
   "바로 진료"), 범위 3(수면 시간은 4~12개월 수치라 항목 재정의, 영아 페이지 항목은 0~11개월), 징후 누락 2
   (머리 부딪힘의 의식 소실, 구토·설사의 HUS 징후), 접속사 1("~하고"→"하나라도"), 오독 소지 1("생우유"→
   "일반 우유"), 출처 맥락 표시(독감·대장균 안내의 경고 목록임을 본문에 적음)
5. `timeline.ts` 목업의 L1 부분을 실데이터로 교체 — **접종·검진 완료(2026-10-01, 4단계보다 먼저)**.
   홈 「챙길 것」과 성장 타임라인이 승인된 지식베이스를 읽는다. 같은 월·분류는 한 줄로 묶고
   (SPEC-HOME-02 묶음), 기간 항목은 기간이 끝나야 놓침으로 본다. 출처 없는 목업 발달·생활 항목은 뺐다 —
   4단계에서 실데이터로 채운다. 위의 로타 RV1 미결은 covers 를 id 목록으로 바꿔 풀었다(기록 하나가
   RV5 전용 3차까지 닫는다 — knowledge-layers 연결 규칙). 실제로 닫는 흐름은 기록 저장 task 에서.
   **발달 반영(2026-10-02)**: 홈 「발달 포인트」가 발달 항목(이정표 요약 + 조기 상담 안내)을 보여주고,
   첫 이정표 전에는 몇 개월인지 알려준다(SPEC-HOME-03). 타임라인 표준 트랙은 접종·검진·발달만 올린다 —
   상시 지식(수유·수면·생활·안전·대응)은 컬럼에 올리지 않는다(SPEC-GROW-02 HOW). 생활 팁은
   「챙길 것」의 생활 항목(SPEC-HOME-02, 따로 task)이 맡는다
6. 국내 출처 보강 — 위험 신호(대응)·수유 기준을 질병관리청 국가건강정보포털 같은 국내 자료와 대조한다.
   포털은 공공누리 제4유형이라 본문 재서술은 하지 않고 사실 확인·링크만 한다(decisions/005)
