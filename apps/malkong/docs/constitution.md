# constitution — 육아버디의 바뀌지 않는 원칙

이 문서는 개별 SPEC 보다 위에 있다. SPEC · task · 코드가 여기와 충돌하면 여기가 이긴다.
바꾸려면 이 문서를 먼저 고치고 이유를 changelog 에 남긴다.

## 제품 원칙

1. **일상에서 깜빡하는 육아 일을 챙긴다.** 목욕 · 터미타임 · 손톱 깎기 같은 루틴(했는지 바로 보이고 정한 시각에 알린다), 그때그때 생기는
   육아용품 장보기와 배송 받을 것, 어린이집 준비처럼 공공에서 챙겨 주지 않는 일이 중심이다. 접종 · 검진, 기념일, 사이즈 바꾸기처럼 앱이 아기 생일과 월령으로 언제 할지 아는 일은 앱이 미리 만들어 둔다.
   사용자가 적는 할 일은 보통 할 일 앱처럼 「내 할 일」에 모이고, 원하면 주제로 묶는다. 정부와 다른 앱이 이미 챙기는 일(지원금 신청 등)은 넣지 않는다
   ([decisions/025](decisions/025-app-filled-topics.md) · [026](decisions/026-everyday-shopping-home-tab.md)).
2. **끝낸 것은 남기고, 다음 차례를 먼저 꺼내 준다.** 끝낸 할 일과 기록은 지우지 않는다. 반복 할 일의 다음 차례,
   여러 번 끝낸 할 일의 반복, 기록에서 계산한 떨어질 때를 먼저 꺼내 준다. 사용자가 직접 지운 것만 지운다.
3. **사실만 저장하고 해석은 그때 계산한다.** 「10월 10일에 3단계 기저귀 64개를 샀다」, 「오늘 기저귀 8번」은 저장하고,
   「기저귀는 사흘 뒤 떨어진다」는 저장하지 않고 볼 때마다 계산한다. 사용자가 고친 값(「분유는 ○○ 2단계로 고정」)은
   그 사람이 정한 사실로 저장하고 계산보다 우선한다.
4. **적기는 쉬워야 한다.** 기록은 한두 번 눌러 남기고, 할 일은 앱을 연 뒤 두 번 터치 안에 적는다. 정리하지 않은 글을 붙여 넣어도
   앱이 할 일로 나눈다. 기록이나 할 일을 남기지 않았다고 탓하는 말을 쓰지 않는다.
5. **의료 판단을 하지 않는다.** 앱은 육아 질문에 답하지 않고, 진단 · 처방 · 정상 판정을 하지 않으며, 할 일로 처치를 권하지 않는다.
   기록이 위험 신호 기준(예: 3개월 미만 38℃ 이상)에 닿으면 정해진 안내 문장을 공공 출처와 함께 보여 줄 뿐이다.
   접종 · 검진은 공공 기관 일정을 그대로 계산해 보여 준다. 공공 지식은 재사용이 허용된 출처 화이트리스트로만 만들고,
   원문을 베끼지 않으며, 항목마다 출처를 기록한다. 출처는 화면마다 적지 않고 「의학 정보 출처와 한계 고지」에 모아 보인다
   ([decisions/024](decisions/024-topic-todo-no-ai-answers.md), Julian 2026-10-22).
6. **알림은 정한 시각에 반드시 울린다.** 기록 알림과 할 일 알림은 서버를 거치지 않고 폰이 직접 울린다. 알림이 안 울린 것은 가장 큰 결함으로 다룬다.
7. **아기 데이터는 민감 정보다.** 기록과 할 일은 기기 안에 저장하고, 서버에는 가족 공유를 켜며 동의한 사본만 둔다.
   광고에 아기 데이터를 넘기지 않는다.
8. **큰 서비스가 하는 일과 계속 관리해야 하는 콘텐츠는 만들지 않는다.** 쇼핑몰 · 가격 비교 · 커뮤니티가 하는 일은 링크로 잇고,
   기본 주제와 가이드처럼 한 번 만들어 두는 것만 둔다. 추천은 우리 가족의 기록에서 나온다.

## 개발 원칙

9. **SPEC 이 먼저다.** 근거 SPEC 없는 기능 코드를 만들지 않는다. SPEC 이 모호하면 지어내지 않고 묻는다.
10. **검증은 구현과 분리한다.** task 를 끝낼 때는 완료 조건(SPEC 문장)과 실제 동작을 대조해 확인하고,
    통과시키려고 조건을 몰래 완화하지 않는다. 규모가 커지면 검증을 별도 세션(에이전트)에 맡긴다.
11. **품질 게이트**: 앱은 `npx tsc --noEmit` + `npx expo lint`, 서버는 `uv run ruff check .` +
    `uv run ruff format --check .` + `uv run pytest` 를 통과하기 전에는 끝났다고 하지 않는다.
12. **스택 · 스타일의 정본은 [app-design](app-design/README.md)** 이고, 무게 있는 선택의 이유는
    [decisions](decisions/README.md)에 남긴다.
13. **AI 모델**은 붙여 넣은 글을 할 일로 나눌 때(선택으로 주제의 추천 목록)만 부른다. 줄마다 하나씩 적힌 글은 규칙으로 먼저 나눈다.
    하루 무료 횟수와 서버 하루 비용 상한을 둔다. 보낸 글을 학습에 쓰지 않는 유료 등급 키만 쓴다.
