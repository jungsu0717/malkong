# constitution — Planmory 의 바뀌지 않는 원칙

이 문서는 모든 SPEC 보다 위에 있다. SPEC, task, 코드가 여기와 부딪히면 여기가 이긴다.
바꾸려면 이 문서를 먼저 고치고 이유를 changelog 에 남긴다.

## 제품 원칙

1. **할 일 적기가 가장 쉬워야 한다.** 할 일 하나는 앱을 연 뒤 두 번 터치 안에 적을 수 있어야 한다. 메신저 메시지나 메모처럼
   정리하지 않은 글을 붙여 넣어도 앱이 할 일로 나눈다. 사람에게 하나씩 옮겨 적게 하지 않는다.
2. **오늘 할 일은 화면 하나에서 끝낸다.** 첫 화면에는 지금 필요한 주제와 오늘 할 일만 두고, 긴 목록은 주제를 눌러 들어가는 상세 화면에 둔다.
3. **할 일은 주제에 속한다.** 주제는 오늘, 퇴근 전, 장보기, 여행, 운동처럼 상황이나 분야다. 주제에는 기간과 함께하는 사람이 있을 수 있다.
4. **끝낸 할 일은 지우지 않는다.** 끝낸 주제는 보관함으로 옮기고, 같은 종류의 주제를 새로 만들 때 지난 할 일을 추천한다.
   사용자가 직접 지운 것만 지운다.
5. **사실만 저장하고 해석은 그때 계산한다.** 「10월 10일에 우유를 서울우유 1.8L 로 샀다」는 저장하고, 「우유는 보통 서울우유」는
   저장하지 않고 볼 때마다 센다. 사용자가 고친 해석(「우유는 서울우유로 고정」)은 그 사람이 정한 사실로 저장하고, 계산보다 우선한다.
6. **알림은 정한 시각에 반드시 울린다.** 내 할 일 알림은 서버를 거치지 않고 폰이 직접 울린다. 알림이 안 울린 것은 가장 큰 결함으로 다룬다.
7. **큰 서비스가 하는 일은 만들지 않는다.** 메신저, 달력, 송금, 모임 회비, 숙소 예약처럼 큰 서비스가 하는 일은 링크 한 줄로 연결할 뿐 따라 만들지 않는다.
8. **계속 관리해야 하는 콘텐츠는 만들지 않는다.** 기본 가이드처럼 한 번 만들어 두는 것만 둔다. 추천은 사용자의 기록에서 나온다.

## 개발 원칙

9. **SPEC 이 먼저다.** 근거 SPEC 없는 기능 코드를 만들지 않는다. SPEC 이 모호하면 지어내지 않고 묻는다.
10. **확인은 구현과 따로 한다.** task 를 끝낼 때 완료 조건과 실제 동작을 대조하고, 통과시키려고 조건을 몰래 완화하지 않는다.
11. **품질 검사**: 앱은 `npx tsc --noEmit` + `npx expo lint`, 서버는 `uv run ruff check .` + `uv run ruff format --check .` +
    `uv run pytest` 를 통과하기 전에는 끝났다고 하지 않는다.
12. **데이터**: 서버(Neon)가 원본이고 폰은 복사본이다. 인터넷이 없어도 적을 수 있고, 연결되면 서버와 맞춘다. 로그인은 Apple 로그인을
    먼저 둔다. 탈퇴하면 서버의 모든 기록(붙여 넣은 원문 포함)을 지운다([decisions/002](decisions/002-server-as-source.md)).
13. **AI 모델**: 붙여 넣은 글을 할 일로 나눌 때와 주제의 시작 목록을 만들 때만 부른다. 줄마다 하나씩 적힌 글은 규칙으로 먼저 나눈다.
    하루 무료 횟수와 서버 하루 비용 상한을 둔다. 보낸 글을 학습에 쓰지 않는 유료 등급 키만 쓴다([decisions/003](decisions/003-ai-two-uses.md)).
