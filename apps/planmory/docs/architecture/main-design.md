# Planmory 전체 설계

> 위에 있는 것: [constitution](../constitution.md) · [product-brief](../product/product-brief.md)

## 화면 구조 — 첫 판

탭은 셋이다. 첫 화면은 「오늘」이다.

| 탭 | 무엇 | SPEC |
|---|---|---|
| **오늘** | 지금 시간에 맞는 주제를 맨 위에, 오늘 할 일, 반복 할 일 제안. 맨 아래에 입력칸이 늘 있어서 열면 바로 적는다 | [today](../menu-spec/today.md) · [add](../menu-spec/add.md) |
| **주제** | 진행 중인 주제와 보관함. 새 주제 만들기(종류 → 추천 할 일과 기본 가이드) | [topic](../menu-spec/topic.md) |
| **마이** | 로그인, 알림, 약관, 탈퇴 | 미결: 첫 판 마이 SPEC 은 로그인 task 와 함께 쓴다 |

둘째 판에 「기록」 탭(쌓인 기록 나무, 말로 묻기)을 더한다. 화면은 한눈 요약과 상세 화면으로 나눈다(루트 AGENTS 「화면은 한눈 요약과 상세 화면으로 나눈다」).

## 할 일이 생기는 길

1. **한 줄 적기** — 입력칸에 쓰고 완료. 지금 보고 있는 주제에 들어간다(오늘 탭이면 「오늘」 주제)
2. **붙여 넣기** — 붙여 넣거나 클립보드 제안을 누르면 나눈 결과를 미리 보여 주고, 고쳐서 저장한다
3. **공유 메뉴** — 메신저 같은 앱에서 Planmory 로 공유하면 붙여 넣기 미리보기가 열린다(개발 빌드가 있어야 확인할 수 있다)
4. **추천 할 일** — 주제를 만들 때와 주제 안에서: 같은 종류의 지난 주제, 기본 가이드, AI 시작 목록(한 번)
5. **반복 할 일** — 끝낸 기록에서 같은 할 일의 간격을 계산해, 다음 날짜가 되면 오늘 탭에 제안한다

## 데이터 — 사실만 저장한다

서버(Neon)가 원본이고 폰(expo-sqlite)은 같은 표의 복사본이다([decisions/002](../decisions/002-server-as-source.md)).
모든 행에 `id`(앱이 만드는 문자열), `created_at`, `updated_at`, `deleted_at`(지운 표시) 이 있다.

| 표 | 칸 |
|---|---|
| `topic` 주제 | 종류(`today` · `before_home` · `shopping` · `trip` · `work` · `exercise` · `event` · `custom`), 이름, 시작일, 끝날, 시간대(예: 17:00~19:00), 반복(없음 · 매일 · 매주 요일), 장소, 보관한 때 |
| `item` 할 일 | 주제, 제목, 메모, 기한, 알림 시각, 생긴 길(`manual` · `paste` · `share` · `suggested` · `repeat` · `starter`), 원문 id, 부탁한 사람, 적은 사람 |
| `item_label` 라벨 | 할 일, 키(`pick` 칩 · `brand` · `size` · `count` · `check`), 값 |
| `completion` 완료 | 할 일, 끝낸 사람, 끝낸 때. 되돌리면 지운 표시 |
| `raw_input` 원문 | 붙여 넣은 글 그대로, 들어온 길(`paste` · `share`) |
| `override` 고친 해석 | 대상(예: 「우유」), 키(예: `brand`), 값, 정한 사람 — 계산한 해석보다 우선한다(헌장 5) |

**저장하지 않고 볼 때마다 계산하는 것**: 반복 간격, 「늘 사던 거」의 브랜드와 용량, 주제의 완성도, 둘째 판의 기록 나무.
같은 할 일인지는 제목에서 띄어쓰기를 뺀 글자가 같은지로 본다. 비슷한 이름(「세제 주문」과 「세제 사기」)을 하나로 볼지는
둘째 판에서 사용자가 합치는 기능으로 푼다.

## 서버

육아버디 서버(`apps/malkong/server`)의 구조를 그대로 쓴다 — FastAPI, Cloud Run, 기기 키, 하루 한도, 서버 하루 비용 상한,
광고 보상 확인, 모델 연결부. 처음에는 복사해 오고, 두 앱이 같이 고치게 되면 `packages/` 로 옮긴다.

| 요청 | 하는 일 |
|---|---|
| `POST /v1/devices` | 로그인 전 기기 키 발급 |
| `POST /v1/auth/apple` | Apple 로그인 토큰을 확인하고 계정을 만들거나 찾는다. 기기 키의 기록을 계정에 묶는다 |
| `POST /v1/sync` | 바뀐 행을 올리고, 그 뒤에 바뀐 행을 받는다(순번, 나중에 쓴 쪽이 이김) |
| `POST /v1/extract` | 글 → 할 일 후보(제목, 날짜, 사람, 라벨). 하루 한도 |
| `POST /v1/starter` | 주제 종류와 이름 → 시작 목록. 하루 한도 |
| `DELETE /v1/account` | 탈퇴. 그 계정의 모든 행을 지운다 |
| `GET /s/<token>` | 공유한 주제의 웹 페이지 — 앱 없이 체크(첫 판 마지막 단계) |

모델은 Gemini Flash-Lite(유료 등급 키)로 시작하고, 결과는 정해진 JSON 모양으로만 받는다. 모델 이름과 가격은 붙일 때 다시 확인한다.

## 알림

- 알림 시각이 있는 할 일은 폰의 로컬 알림(expo-notifications)으로 건다. 할 일을 고치거나 끝내거나 지우면 다시 건다.
  폰을 바꿔 로그인하면 받아 온 기록으로 다시 건다
- 반복 할 일 제안이 있는 날은 아침에 로컬 알림 한 번
- 함께 쓰는 주제에서 누가 체크하면 알리는 서버 푸시는 둘째 판
- 알림 허락은 처음 알림 시각을 넣을 때 묻는다
